Uma linguagem de 1972 que roda o mundo

O C nasceu nos Bell Labs, nos Estados Unidos, durante os anos 1970. Dennis Ritchie o criou a partir do B (que deriva do BCPL), com um objetivo bem prático: reescrever o sistema operacional Unix, que até então era escrito em assembly. Para escrever um SO portátil, Ritchie precisava de uma linguagem que fosse rápida quanto assembly, mas legível e portável como as linguagens de alto nível.

O C "decolou" junto com o Unix: como o SO era escrito em C, qualquer máquina que tivesse um compilador C podia rodar o Unix. Da Bell Labs, a linguagem se espalhou pelas universidades e depois pela indústria inteira.

  • 1972 — primeiras versões do C, ainda junto ao Unix (PDP-11).
  • 1978 — livro clássico de Kernighan & Ritchie (The C Programming Language), o famoso "K&R".
  • 1989/1990 — padronização oficial (ANSI C / C89, depois ISO C90).
  • 1999 — padrão C99 (designated initializers, // para comentário, variantes de tipos).
  • 2011 — padrão C11, o que usamos neste curso (_Bool, _Static_assert).
  • 2018 / 2023 — C17 (correções) e C23 (última revisão).

Por que C segue na frente

Décadas depois, o C continua entre as linguagens mais usadas do mundo — ocupa regularmente o topo de rankings como o TIOBE. O motivo é que ele resolve, com precisão e previsibilidade, problemas que quase nenhuma outra linguagem resolve:

  • Kernels de sistemas operacionais — Linux, Windows, macOS: o núcleo é escrito em C.
  • Embarcados e IoT — microcontroladores com KB de memória não suportam máquina virtual; sobra espaço só para C (e assembly).
  • Compiladores e interpretadores — inclusive vários compiladores de linguagens "modernas".
  • Bibliotecas de alto desempenho — de banco de dados a motores de jogo, os "miolos" caros são C/C++.
  • Camadas de baixo nível — drivers, firmware, protocolos de rede. É onde "a borracha pega".

Filosofia: "o C confia em você"

Ao contrário de linguagens que seguram sua mão (Java, Python, Go), o C assume que você sabe o que está fazendo. Ele permite acessar a memória diretamente, não cria "garbage collector" e não esconde o que o processador realmente faz. Consequência: você ganha velocidade e controle, e paga com responsabilidade.

Na prática, isso aparece em situações como: escrever além do fim de um vetor compila? não: compila, mas o comportamento é indefinido; somar dois inteiros que estouram o limite "silenciosamente"; comparar com = em vez de ==. O C não vai te impedir — cabe a você se cuidar (e a nós, ensiná-lo a se cuidar).

Essa é a mesma razão pela qual a Trilha 4 (Cyber) deste curso existe: bugs de C se tornam vulnerabilidades. Entender bem o C é entender segurança ofensiva e defensiva.

O que você consegue fazer com C

Neste curso você vai do "olá, mundo" a um utilitário de linha de comando completo no módulo 1.12 — tudo com o gcc e o terminal que você já configurou na Trilha 0.

  • Escrever utilitários de linha de comando (o que você fará até o fim desta trilha).
  • Programar microcontroladores e robôs (Arduino, ESP32, ...).
  • Implementar estruturas de dados e algoritmos do zero, sem depender de frameworks.
  • Ler e manipular dados brutos: arquivos, rede (sockets), formatos binários.
  • Construir sua própria linguagem, emulador ou sistema operacional.
  • Entrar a fundo em segurança: análise de binários, exploits, engenharia reversa.

Seu programa de novo, agora com atenção

Compile e rode o programa abaixo. Repare que ele é idêntico em estrutura a qualquer outro programa C: a diretiva #include traz a biblioteca, a função main é o ponto de entrada, as instruções terminam com ; e o return 0 sinaliza sucesso para o sistema operacional.

Código — hello de novo
#include <stdio.h>

int main(void)
{
    printf("Olá, mundo!\n");
    printf("Trilha 1 começa aqui\n");
    return 0;
}
Saída esperada
Olá, mundo!
Trilha 1 começa aqui

Do código ao executável (recapitulando)

Você já viu isso na Trilha 0, mas vale fixar o ciclo. C é uma linguagem compilada: você escreve o texto em um arquivo .c, o gcc traduz tudo para código de máquina e então você executa o resultado. Diferente de linguagens interpretadas, que leem e executam linha a linha "na hora".

  • gcc -Wall -Wextra -std=c11 hello.c -o hello — compila e linka, gerando hello.exe.
  • .\hello.exe — executa o programa, que roda a função main.
  • Erros de sintaxe aparecem na compilação; erros de lógica aparecem na execução. Esta distinção será vital no módulo 1.11.

✏️ Exercícios

Nível 1

Exercício 1.01.1

Modifique o programa hello.c para imprimir seu primeiro nome na primeira linha e a cidade onde você mora na segunda. Compile com -Wall -Wextra e garanta zero avisos.

Dica: Dois printf separados bastam; só não esqueça o \n de cada linha.

Ver solução
#include <stdio.h>

int main(void)
{
    printf("Maria\n");
    printf("Recife\n");
    return 0;
}

Troque os nomes por você mesmo(a). O importante é o fluxo: editar, compilar, executar, ver a saída.

Nível 1

Exercício 1.01.2

Escreva um programa que imprime um triângulo de quatro linhas de asteriscos: começa com 1 e termina com 4 asteriscos.

Dica: Cada linha é um printf com o número certo de * seguido de \n.

Ver solução
#include <stdio.h>

int main(void)
{
    printf("*\n");
    printf("**\n");
    printf("***\n");
    printf("****\n");
    return 0;
}
Nível 2

Exercício 1.01.3

Use printf para montar uma mini tabela de preços com duas colunas (item e preço) separadas por um caractere de tabulação \t. Ex.: Caneta\t2.50.

Dica: O caractere de tabulação é escrito em C como \t.

Ver solução
#include <stdio.h>

int main(void)
{
    printf("Item\tPreco\n");
    printf("Caneta\t2.50\n");
    printf("Lapis\t1.90\n");
    printf("Total\t4.40\n");
    return 0;
}

A tabulação alinha as colunas sem você contar espaços na mão.

Nível 2

Exercício 1.01.4

Sem rodar, escreva no papel a saída do programa abaixo. Depois compile, rode e compare: printf("2 + 2 = %d\n", 4); e printf("%d + %d = %d\n", 2, 2, 4);.

Dica: %d é o lugar onde o número entra no texto.

Ver solução
#include <stdio.h>

int main(void)
{
    printf("2 + 2 = %d\n", 4);
    printf("%d + %d = %d\n", 2, 2, 4);
    return 0;
}

Os dois printf produzem exatamente a mesma linha. %d substitui o valor do argumento no texto.
