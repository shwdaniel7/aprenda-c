As armadilhas clássicas do C

A maior parte do tempo de um iniciante é devorado por um punhado de bugs que se repetem. Conheça o crime para reconhecer o criminoso:

  • Ponto e vírgula esquecido — o gcc acusa na linha seguinte. Corrija o primeiro erro primeiro.
  • = no lugar de == — o programa compila e a condição vira sempre verdadeira. O gcc avisa com -Wall ("suggest parentheses").
  • Off-by-one — usar <= onde deveria ser <, ou percorrer 1..n em vez de 0..n-1. Compila perfeitamente.
  • Esquecer & no scanf — o scanf recebe um valor em vez de um endereço; com -Wall há warning, e em execução costuma estourar.
  • Tipo errado no printf — %f com int, %d com double... comportamento indefinido, e o -Wall -Wformat denuncia.
  • Comparar double com == — ponto flutuante arredonda; use margem de erro.

Como ler um warning (e o infame = vs ==)

Um warning é o compilador dizendo "isso provavelmente não é o que você quer". O formato é arquivo:linha:coluna: warning: mensagem [-Wtipo]. O trecho [-W...] identifica a família do aviso. Compile com -Wall -Wextra e trate qualquer warning como erro em potencial.

Código — warnings
#include <stdio.h>

int main(void)
{
    int x = 2;

    if (x = 3) {   /* BUG: atribuicao, nao comparacao */
        printf("x vale 3\n");
    }
    return 0;
}
Saída esperada
bug.c:7:9: warning: suggest parentheses around assignment used as truth value [-Wparentheses]
    7 |     if (x = 3) {   /* BUG: atribuicao, nao comparacao */
      |         ^

x vale 3

O scanf sem &: a receita do desastre

Escrever scanf("%d", x); em vez de scanf("%d", &x); é o erro mais famoso de todos. O compilador avisa (veremos o warning real), e na execução o scanf tenta gravar em um endereço "sem sentido" — na prática, comportamento indefinido.

Código — scanf sem &
#include <stdio.h>

int main(void)
{
    int x;

    printf("Digite um numero: ");
    scanf("%d", x);   /* BUG: faltou o & */
    printf("voce digitou: %d\n", x);
    return 0;
}
Saída esperada
bug2.c: In function 'main':
bug2.c:8:13: warning: format '%d' expects argument of type 'int *', but argument 2 has type 'int' [-Wformat=]
    8 |     scanf("%d", x);   /* BUG: faltou o & */
      |            ~^   ~
      |             |   |
      |             |   int
      |             int *
bug2.c:8:5: warning: 'x' is used uninitialized [-Wuninitialized]
    8 |     scanf("%d", x);   /* BUG: faltou o & */
      |     ^~~~~~~~~~~~~~
bug2.c:5:9: note: 'x' was declared here
    5 |     int x;
      |         ^

O off-by-one no espelho

O off-by-one não dá warning: ele roda errado e nada fala. Compare o bug com a correção — a diferença é um sinal de comparação:

Código — off-by-one
#include <stdio.h>

int main(void)
{
    int soma = 0;
    int i;

    for (i = 1; i <= 7; i++) {   /* BUG: deveria ser i <= 5 */
        soma += i;
    }

    printf("soma de 1 a 5: %d\n", soma);
    return 0;
}
Saída esperada
soma de 1 a 5: 28

Depuração por printf: seu primeiro detector

Quando o programa compila e roda mas faz o contrário do esperado, imprima o que você está pensando: printf("i=%d, soma=%d\n", i, soma); dentro do loop. Você vê a evolução das variáveis e acha o instante exato em que algo sai dos trilhos. Retire (ou comente) os prints de depuração ao terminar — código limpo não tem lixo.

assert: a trava que para o programa

O assert (de <assert.h>) avalia uma condição e, se for falsa, aborta o programa imprimindo o que falhou, o arquivo e a linha. É perfeito para pré-condições: "aqui, matematicamente, isto tem que ser verdade". Se algum dia não for, você quer descobrir agora.

Código — assert
#include <stdio.h>
#include <assert.h>

int divide(int a, int b)
{
    assert(b != 0);
    return a / b;
}

int main(void)
{
    printf("10 / 2 = %d\n", divide(10, 2));
    printf("8 / 0 = %d\n", divide(8, 0));   /* assert trava aqui */
    printf("nunca chega aqui\n");
    return 0;
}
Saída esperada
10 / 2 = 5
Assertion failed: b != 0, file assert_demo.c, line 6

gdb: o passo a passo de verdade

Compilado com -g, o programa carrega "mapa" de linhas e variáveis. Os quatro comandos que resolvem 90% dos casos: break (para em uma linha/função), next (executa próxima linha, sem entrar em função), step (entra em função), print (mostra o valor de uma variável).

Código — gdb
gcc -g -Wall -Wextra -std=c11 prog.c -o prog
gdb ./prog.exe
(gdb) break main
(gdb) run
(gdb) next
(gdb) print soma
(gdb) print i
(gdb) step
(gdb) continue
(gdb) quit

A versão corrigida

O mesmo programa, certo:

Código — correção
#include <stdio.h>

int main(void)
{
    int soma = 0;
    int i;

    for (i = 1; i <= 5; i++) {
        soma += i;
    }

    printf("soma de 1 a 5: %d\n", soma);
    return 0;
}
Saída esperada
soma de 1 a 5: 15

✏️ Exercícios

Nível 3

Exercício 1.11.1

Encontre e corrija os dois erros no código: falta um & no scanf e um ponto e vírgula está faltando em uma das linhas.

Dica: Compile com -Wall e leia arquivo:linha. O primeiro erro bloqueia, o segundo aparece depois.

Ver solução
#include <stdio.h>

int main(void)
{
    int n;

    printf("Digite um numero: ");
    scanf("%d", &n);

    printf("voce digitou: %d\n", n);
    return 0;
}

O enunciado intencionalmente tinha scanf("%d", n); e printf(...) sem ponto e vírgula.

Nível 3

Exercício 1.11.2

O programa abaixo soma as notas até digitar 0, mas está devolvendo valores estranhos. Depure com printf de depuração (ou gdb) e corrija: int n; int soma = 0; do { scanf("%d", &n); soma += n; } while (n != 0);. O bug: ele soma o 0 final na média errada de notas — refaça para não contar o 0 sentinela.

Dica: aumente o soma apenas quando n != 0.

Ver solução
#include <stdio.h>

int main(void)
{
    int n;
    int soma = 0;

    printf("Digite notas (0 encerra):\n");
    do {
        printf("> ");
        scanf("%d", &n);
        if (n != 0) {
            soma += n;
        }
    } while (n != 0);

    printf("total: %d\n", soma);
    return 0;
}
Nível 3

Exercício 1.11.3

Use assert para validar que uma função de divisão não recebe divisor zero, e faça um main que teste a função com 0 para ver o programa abortar com a mensagem do assert.

Dica: Inclua . A mensagem mostrada inclui arquivo e linha.

Ver solução
#include <stdio.h>
#include <assert.h>

double dividir(double a, double b)
{
    assert(b != 0.0);
    return a / b;
}

int main(void)
{
    printf("%.2f\n", dividir(10.0, 4.0));
    printf("%.2f\n", dividir(10.0, 0.0));
    return 0;
}

Ao rodar, o programa imprime "2.50" e depois aborta no assert—a mensagem mostrada inclui arquivo e linha.

Nível 4

Exercício 1.11.4

O programa seguinte percorre um array de 5 posições, mas imprime um valor lixo na última execução. Descubra o off-by-one e corrija: int v[5] = {10,20,30,40,50}; for (i = 1; i <= 5; i++) printf("%d ", v[i]);.

Dica: v[5] não existe! O laço vai de 0 a 4.

Ver solução
#include <stdio.h>

int main(void)
{
    int v[5] = {10, 20, 30, 40, 50};
    int i;

    for (i = 0; i < 5; i++) {
        printf("%d ", v[i]);
    }
    printf("\n");
    return 0;
}

O valor lixo vinha da leitura fora dos limites (UB). Percorrimento de array é sempre 0..n-1.

Nível 4

Exercício 1.11.5

Crie um programa com o erro = no lugar de == (ex.: decidir se o usuário digitou a senha 1234). Compile SEM -Wall, rode, veja a condição sempre "verdadeira"; depois compile COM -Wall e leia o warning. Corrija o programa.

Dica: Warnings são seus amigos: para a condição de senha compare com ==.

Ver solução
#include <stdio.h>

int main(void)
{
    int senha;

    printf("Digite a senha: ");
    scanf("%d", &senha);

    if (senha == 1234) {
        printf("acesso liberado\n");
    } else {
        printf("acesso negado\n");
    }
    return 0;
}

No bug, if (senha = 1234) sempre "passava", pois o valor da atribuição é 1234 (verdadeiro).
