Escopo, duração e organização

onde as variáveis vivem e por quanto tempo

Escopo de bloco: a variável que só existe na chave

Tudo o que é declarado dentro de { } (um bloco) existe apenas dentro dele: é o escopo de bloco. Fora do bloco, a variável não é visível — e o mesmo nome pode ser reutilizado em outro bloco. Uma variável declarada dentro da função é "local" à função; um for com a própria variável (int i) é uma das formas preferidas de limitar até onde ela vale.

Sombreamento: se um bloco interno declara um nome igual ao de um bloco externo, o interno "esconde" o externo (shadowing). É legal, mas confunde — evite.

Escopo de arquivo (globais): fique de olho

Declarar fora de toda função cria uma variável de escopo de arquivo (global): visível em todo o arquivo, de qualquer função. Isso pode parecer prático (não precisa passar parâmetro), mas é uma armadilha: qualquer função pode alterar, e o fluxo do programa vira uma sopa. A regra de ouro deste módulo: use parâmetros e retornos — evite globais.

Código — globais
#include <stdio.h>

int total_bruto = 0;   /* global: visivel em todo o arquivo */

void soma_bruto(int valor)
{
    total_bruto += valor;
}

int main(void)
{
    soma_bruto(10);
    soma_bruto(25);

    printf("total bruto: %d\n", total_bruto);
    return 0;
}
Saída esperada
total bruto: 35

Duração: automática vs estática

Escopo é onde o nome é visível; duração é por quanto tempo o espaço existe na memória. são dois conceitos independentes!

  • Automática (padrão para locais): a variável é criada na entrada do bloco e destruída na saída. Cada chamada de função "recomeça do zero".
  • Estática (static na declaração): o espaço persiste a vida inteira do programa; a variável guarda seu valor entre chamadas, mesmo dentro da função.
  • Uma variável local static tem duração estática, mas escopo de bloco (só é acessível dentro). É o melhor dos dois mundos para "lembrar" sem poluir o global.

static local: o estado que sobrevive

Aqui está o truque clássico: uma variável estática local que conta quantas vezes a função foi chamada. Estática local OU global? Ou ambas — cada uma com seu escopo.

Código — static
#include <stdio.h>

int proximo_id(void)
{
    static int contador = 0;   /* preservado entre chamadas */
    contador++;
    return contador;
}

int main(void)
{
    printf("id: %d\n", proximo_id());
    printf("id: %d\n", proximo_id());
    printf("id: %d\n", proximo_id());
    return 0;
}
Saída esperada
id: 1
id: 2
id: 3

Boas práticas de organização

  • Declare as variáveis no menor escopo possível — perto do uso, dentro do menor bloco que precisa dela.
  • Preira parâmetros + retorno a globais: a função fica previsível e testável.
  • Dê nomes claros. Uma função deve caber em um sentido (ex.: media, eh_primo).
  • Uma função, uma responsabilidade. Se você precisa de comentário "e aqui faz também", divida.
  • Use constantes com const para valores que não devem mudar.
  • Quando (e somente quando) precisar de estado persistente, prefira static local a global.

Múltiplos arquivos: a ideia em vinte segundos

Programas reais se dividem em vários arquivos: um .c implementa e um .h declara (protótipos + constantes) — assim outras partes #include o .h e usam as funções sem precisar dos detalhes. O gcc compila todos os .c juntos: gcc main.c util.c util.h -o prog. Os mecanismos finos (headers, makefiles, linkagem) ficam para a Trilha 2; aqui você só precisa saber que o padrão existe e qual é o "o quê" de cada arquivo.

✏️ Exercícios

Nível 2

Exercício 1.10.1

Escreva uma função novo_id(void) com uma variável estática que retorna 1, 2, 3... a cada chamada, e um main que chama 5 vezes imprimindo os ids.

Dica: Estática local: static int n = 0; e n++.

Ver solução
#include <stdio.h>

int novo_id(void)
{
    static int n = 0;
    n++;
    return n;
}

int main(void)
{
    int i;

    for (i = 1; i <= 5; i++) {
        printf("id %d: %d\n", i, novo_id());
    }
    return 0;
}
Nível 2

Exercício 1.10.2

Preveja a saída do programa abaixo (que tem sombreamento) e depois confirme rodando: uma variável global x = 1, um main que declara x = 2 e um bloco interno declara x = 3, imprimindo na ordem.

Dica: O nome mais interno "vence" dentro do seu escopo.

Ver solução
#include <stdio.h>

int x = 1;   /* global */

int main(void)
{
    int x = 2;   /* local de main */

    printf("1) %d\n", x);

    {
        int x = 3;   /* local do bloco interno */
        printf("2) %d\n", x);
    }

    printf("3) %d\n", x);
    return 0;
}

Imprime 2, 3, 2: o x interno vale apenas dentro do próprio bloco.

Nível 3

Exercício 1.10.3

Refatore: o código abaixo usa uma global saldo. Reescreva-o sem global, com saldo local em main e funções que recebem/retornam o valor.

Dica: Crie int depositar(int saldo, int valor) retornando o novo saldo.

Ver solução
#include <stdio.h>

int depositar(int saldo, int valor)
{
    return saldo + valor;
}

int sacar(int saldo, int valor)
{
    if (valor <= saldo) {
        return saldo - valor;
    }
    return saldo;
}

int main(void)
{
    int saldo = 100;

    saldo = depositar(saldo, 50);
    printf("apos deposito: %d\n", saldo);

    saldo = sacar(saldo, 130);
    printf("apos saque: %d\n", saldo);

    saldo = sacar(saldo, 130);
    printf("apos saque (negado): %d\n", saldo);
    return 0;
}

Nenhuma variável global. O histórico do saldo vive no main e "viaja" pelos parâmetros/retornos. O segundo saque de 130 é recusado porque o saldo (20) não cobre o valor.

Nível 3

Exercício 1.10.4

Crie uma função proxima_par(int n) que, para n par, retorna n e para ímpar retorna n+1 — mas use uma estática local para guardar o último valor devolvido e imprima-o.

Dica: A estática guarda o "último retorno"; lembre de usar apenas dentro da função.

Ver solução
#include <stdio.h>

int proxima_par(int n)
{
    static int ultimo = 0;

    if (n % 2 != 0) {
        n = n + 1;
    }
    ultimo = n;
    printf("  (ultimo devolvido: %d)\n", ultimo);
    return n;
}

int main(void)
{
    printf("proxima_par(5): %d\n", proxima_par(5));
    printf("proxima_par(6): %d\n", proxima_par(6));
    return 0;
}
Nível 3

Exercício 1.10.5

Escreva um contador de eventos: uma função registrar(void) que incrementa um total (estático), uma consultar(void) que retorna o total e uma resetar(void) que zera. Um main que registra 3x, consulta, reseta e consulta de novo.

Dica: Todas as três precisam enxergar a MESMA variável estática — declare-a em escopo de arquivo mas com static (internal linkage), assim ela não vaza para o resto: static int total; no topo.

Ver solução
#include <stdio.h>

static int total = 0;   /* static de arquivo: visivel so neste .c */

void registrar(void)
{
    total++;
}

int consultar(void)
{
    return total;
}

void resetar(void)
{
    total = 0;
}

int main(void)
{
    registrar();
    registrar();
    registrar();

    printf("total: %d\n", consultar());

    resetar();
    printf("apos reset: %d\n", consultar());
    return 0;
}

O static de arquivo dá "privacidade": só este arquivo enxerga a variável — um meio-termo entre global pública e local.

🏗️ Miniprojeto: Painel de estatísticas do jogador

Crie painel.c: um "painel" em que várias funções compartilham estado: ganhar(int pts), perder(int pts), consultar_pontos(), consultar_partidas() e resetar(). Use static de arquivo para os contadores, funções pequenas e um menu do-while que lê comandos (g de ganhar, p de perder, c consultar, r resetar, s sair).

Critérios de aceite

  • Estado compartilhado via static de arquivo (sem globais não estáticos).
  • 5+ funções pequenas com responsabilidades únicas.
  • Menu do-while com scanf e switch/if.
  • Sem avisos com -Wall -Wextra -std=c11.
