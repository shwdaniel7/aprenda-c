A vida fora do main: ambiente, saída e interação

argv/argc, variáveis de ambiente, stdin/stdout/stderr e códigos de saída: a interface invisível entre o seu programa e o resto do sistema.

Nível: Avançado Duração: ~45 min Pré-requisitos: Conhecer funções e passagem de argumentos (T1.12). Saber trabalhar com vários arquivos (T2.09). Tratar erros com elegância (T3.01).

🎯 Objetivos

Entender o contrato que todo programa C tem com o sistema operacional: parâmetros da linha de comando (argc/argv), variáveis de ambiente (getenv), os três fluxos padrão (stdin/out/err), buffers e códigos de saída — e como montar pequenas ferramentas de linha de comando que participam de pipes e redirecionamentos como os utilitários UNIX clássicos (grep, cat, head, wc).

Foco da leitura: Foque em argc/argv (ler argumentos com loops sobre argv), getenv (variáveis de ambiente) e a sintaxe de redirect/pipes para testar.

argv/argc: os parâmetros da linha de comando

Todo programa C recebe do sistema operacional a linha de comando que o chamou: argc conta quantos itens (strings) vieram e argv é um vetor de strings com elas. argv[0] é o próprio nome/caminho do programa; argv[1] em diante são os argumentos do usuário.

É com esse vetor que ferramentas como head, wc e o seu próprio utilitário decidem o que fazer. No exemplo, imprimimos a contagem e todos os argumentos — incluindo o caminho completo do executável no Windows.

Duas escolhas de design importantes: (a) nunca assuma que o usuário passou o argumento que você espera — valide argc; (b) para opções curtas (-v, -n 5), compare com strcmp.

  • argc — quantidade de strings em argv (≥ 1).
  • argv[0] — nome/caminho do programa; argv[argc] é sempre NULL.
  • Argumentos são sempre strings: números precisam de atoi()/strtol().
  • Valide argc antes de usar argv[1] em diante.
Código — t3m1101
#include <stdio.h>

int main(int argc, char *argv[]) {
    printf("argc = %d\n", argc);
    for (int i = 0; i < argc; i++) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }
    return 0;
}
Saída esperada
> .argv-info.exe um dois tres
> argv[1] = um
> argv[2] = dois
> argv[3] = tres

O ambiente: getenv() e as variáveis de ambiente

Além da linha de comando, o sistema entrega ao processo um ambiente: um conjunto de pares chave=valor que configura a execução (PATH, USER, COMPUTERNAME, HOME...). Em C, getenv(nome) devolve a string do valor ou NULL se não existir.

É por isso que programas leem configuração sem pedir nada ao usuário: você pode usar o getenv para obter um diretório de logs, um nível de verbosidade, uma flag de debug. No Windows, USERNAME e COMPUTERNAME costumam existir; HOME costuma não ser definido.

O retorno NULL de getenv é seu amigo: sempre trate. Nunca imprima o ponteiro direto sem checar, senão a função imprime "(null)" (indefinido).

  • getenv("NOME") — devolve o valor (string) ou NULL.
  • Variáveis comuns no Windows: USERNAME, COMPUTERNAME, PATH.
  • Sempre teste o retorno antes de usar (evita impressão de NULL).
  • Outra via: o parâmetro envp[] de main — fornecido sem garantia no padrão.
Código — t3m1102
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    const char *user = getenv("USERNAME");
    const char *comp = getenv("COMPUTERNAME");
    const char *path = getenv("PATH");

    printf("USERNAME     = %s\n", user ? user : "(nao definido)");
    printf("COMPUTERNAME = %s\n", comp ? comp : "(nao definido)");
    printf("PATH (ini)   = %s\n", path ? path : "(nao definido)");

    const char *x = getenv("VARIAVEL_INEXISTENTE");
    printf("VARIAVEL_INEXISTENTE = %s\n", x ? x : "(nao definido)");

    return 0;
}

stdin, stdout e stderr: os três fluxos padrão

Qualquer processo em um sistema moderno herda três fluxos de I/O pré-abertos: stdin (entrada), stdout (saída normal) e stderr (mensagens de erro/diagnóstico). O sistema operacional não os distingue por destino — quem decide é quem invoca o processo, via redirecionamento.

A distinção entre stdout e stderr não é cosmética: ela existe para que, num pipe (progA | progB), apenas a saída de dados flua para o pipe, enquanto erros podem ir para o terminal, para um arquivo (2>) ou sumir (2>NUL).

No exemplo, escrevemos em stdout os dados e em stderr o diagnóstico começando com "iniciando". Redirecionando apenas o stdout, o diagnóstico ainda aparece — foi para o stderr.

  • Três fluxos pré-abertos: stdin, stdout, stderr (já declarados em <stdio.h>).
  • printf = stdout; fprintf(stderr, ...) = diagnóstico.
  • Pipe: captura só o stdout do produtor; stderr segue para o terminal, salvo redireção.
  • No Windows: prog 1>saida.txt 2>erros.txt e prog | filtro.
Código — t3m1103
#include <stdio.h>

int main(void) {
    fprintf(stderr, "iniciando processamento\n");

    int linhas = 0;
    char buf[256];
    while (fgets(buf, sizeof buf, stdin)) {
        printf("%s", buf);
        linhas++;
    }

    fprintf(stderr, "linhas processadas: %d\n", linhas);
    return 0;
}
Saída esperada
> (echo primeira linha; echo segunda linha; echo terceira linha; echo quarta linha) | .iltro.exe 2> saida.txt
> [stderr] iniciando processamento
> [stderr] linhas processadas: 4
> [stdout, no arquivo saida.txt]
> primeira linha
> segunda linha

Códigos de saída: a linguagem do sucesso

Quando um programa termina, ele devolve ao shell um código de saída: 0 para sucesso, qualquer outro valor para falha (por convenção, 1 para erro genérico). O Windows olha isso em $LASTEXITCODE no PowerShell, e scripts usam esse número para decidir se continuam.

Você controla o código de três formas: pelo return da main, por exit(codigo) (que funciona de qualquer ponto, inclusive dentro de funções) e por _Exit(codigo). A diferença prática: exit roda os atexit e "flushes" a saída; _Exit pula tudo.

O programa de exemplo testa as três vias. É a base para criar seus próprios "utilitários" que os scripts do Quality System conseguem interpretar.

  • 0 = sucesso; não-zero = falha (convenção: 1 genérico, específicos para casos próprios).
  • return da main e exit(c) são equivalentes na prática.
  • atexit() registra funções chamadas no exit normal.
  • Leia o código do shell: PowerShell usa $LASTEXITCODE.
Código — t3m1104
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void fim_de_jogo(void) {
    printf("(atexit) encerramento normal detectado\n");
}

int main(int argc, char *argv[]) {
    atexit(fim_de_jogo);

    if (argc < 2) {
        fprintf(stderr, "uso: %s <palavra>\n", argv[0]);
        return 2;
    }

    if (strcmp(argv[1], "ok") == 0) {
        printf("tudo certo\n");
        return 0;
    }

    if (strcmp(argv[1], "erro") == 0) {
        fprintf(stderr, "algo deu errado\n");
        return 1;
    }

    printf("codigo de saida customizado: 42\n");
    exit(42);
}
Saída esperada
> .atexit.exe
> (com argumento "ok")
> tudo certo
> (atexit) encerramento normal detectado
> [exit 0]
> (com argumento "erro")
> algo deu errado
> [stderr, exit 1]
> (com argumento "anything")
> codigo de saida customizado: 42
> [exit 42]

Ferramenta 1: um eco que repete argumentos

Vamos construir algo útil com o que temos: um eco de linha de comando que repete os argumentos, um por linha, com índice. É o "cat de argumentos" — e o embrião de utilitários maiores.

Aqui a validação de numero de argumentos e o loop sobre argv aparecem na prática. Passe sem argumentos e o programa avisa e sai com código 1 em vez de quebrar.

Detalhe profissional: o rotulo [1], [2]... ajuda o usuário a conferir, e o loop usa argc como teto — nunca estoura o vetor.

  • Loop sobre argv de 1 até argc-1: for (int i = 1; i < argc; i++).
  • Imprima com printf dentro do loop, rotulando índice.
  • Sem argumentos: avise no stderr e retorne 1.
  • Esse padrão é a espinha dorsal de head, wc, grep-lite.
Código — t3m1105
#include <stdio.h>

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "uso: %s <palavra> [palavra ...]\n", argv[0]);
        return 1;
    }

    for (int i = 1; i < argc; i++) {
        printf("[%d] %s\n", i, argv[i]);
    }

    return 0;
}
Saída esperada
> .exit-codigos.exe um dois
> [1] um
> [2] dois

Ferramenta 2: leitura interativa numérica

Terminamos com a melhor prática de interação: ler um número do usuário de forma segura. Em vez de scanf direto (frágil), ler a linha inteira com fgets e parsear com strtol confiando no retorno.

strtol devolve o número e, se você passar &fim, deixa nele o endereço onde o número terminou — se a linha tiver lixo após o número, *fim não aponta para o '\n'. Essa é a checagem da "entrada toda válida".

O loop pede até o usuário digitar 0 ou um número de 1 a 5; entradas ruidosas são rejeitadas com mensagem clara, sem travar. É o padrão de qualquer menu de Quality System.

  • fgets para capturar a linha; strtol para converter.
  • Cheque o retorno de strtol e o *fim (lixo após o número).
  • errno pode indicar overflow; zere antes de chamar.
  • Mantenha o loop até uma entrada válida — nunca recorra a recursão para isso.
Código — t3m1106
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>

int main(void) {
    while (1) {
        printf("digite um numero de 1 a 5 (0 para sair): ");
        fflush(stdout);

        char linha[64];
        if (!fgets(linha, sizeof linha, stdin)) break;

        errno = 0;
        char *fim = NULL;
        long val = strtol(linha, &fim, 10);

        if (fim == linha || errno == ERANGE || (*fim != '\n' && *fim != '\0')) {
            printf("entrada invalida, tente novamente\n");
            continue;
        }

        if (val == 0) {
            printf("saindo\n");
            break;
        }
        if (val < 1 || val > 5) {
            printf("fora da faixa (1 a 5)\n");
            continue;
        }

        printf("num: %ld\n", val);
    }

    return 0;
}
Saída esperada
> .entrada-segura.exe
> digite um numero de 1 a 5 (0 para sair): set
> entrada invalida, tente novamente
> digite um numero de 1 a 5 (0 para sair): 3
> num: 3
> digite um numero de 1 a 5 (0 para sair): 0
> saindo
> 
> (Entrada simulada com "set", "3", "0".)

Exercício 3.11.1

Liste todas as variáveis de ambiente de interesse: imprima USERNAME, COMPUTERNAME e HOME/USERPROFILE (numa segunda tentativa, se não existir, imprima "nao definida"), e PATH por inteiro. Use getenv com fallback.

Dica: Um helper imprime nome e valor, tratando NULL: printf("%s = %s\n", n, v ? v : "(nao definido)").

Ver solução
#include <stdio.h>
#include <stdlib.h>

void mostra(const char *nome) {
    const char *v = getenv(nome);
    printf("%s = %s\n", nome, v ? v : "(nao definido)");
}

int main(void) {
    mostra("USERNAME");
    mostra("COMPUTERNAME");
    mostra("USERPROFILE");
    mostra("PATH");
    return 0;
}

Exercício 3.11.2

Crie um filtro de grep-lite: leia linhas da stdin e imprima em stdout apenas as que contêm a palavra recebida em argv[1]; em stderr, imprima quantas linhas tinham a palavra. Teste com o arquivo notas.txt (caneta azul, borracha branca, lapis vermelho, regua caneta e lapis) buscando "caneta".

Dica: Use strstr(buf, palavra) para buscar; conte as ocorrências; escreva o total com fprintf(stderr,...).

Ver solução
#include <stdio.h>
#include <string.h>

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "uso: %s <palavra>\n", argv[0]);
        return 1;
    }

    char buf[512];
    int vistos = 0;
    while (fgets(buf, sizeof buf, stdin)) {
        if (strstr(buf, argv[1])) {
            printf("%s", buf);
            vistos++;
        }
    }

    fprintf(stderr, "linhas com '%s': %d\n", argv[1], vistos);
    return 0;
}

./ex11_2 — say com Get-Content notas.txt | .\ex11_2.exe caneta imprime 2 linhas no stdout (caneta azul; regua caneta e lapis) e o total no stderr.

Nível Avançado

Exercício 3.11.3

Escreva um utilitario reverse que inverte os caracteres de cada linha da stdin e imprime na stdout. Teste com uma linha "abc" e confira o resultado "cba".

Dica: Leia com fgets, remova o \n final (strcspn), e imprima os caracteres de tras para frente com um loop de strlen-1 a 0.

Ver solução
#include <stdio.h>
#include <string.h>

int main(void) {
    char buf[512];
    while (fgets(buf, sizeof buf, stdin)) {
        buf[strcspn(buf, "\n")] = '\0';
        size_t n = strlen(buf);
        for (size_t i = n; i > 0; i--) {
            putchar(buf[i - 1]);
        }
        putchar('\n');
    }
    return 0;
}

./ex11_3 — com "abc" imprime "cba".

Nível Avançado

Exercício 3.11.4

Implemente um head-lite: receba um número N em argv[1] e imprima as N primeiras linhas da stdin na stdout. Teste com N=2 e o notas.txt, conferindo as duas primeiras linhas.

Dica: Converta com atoi ou strtol; conte as linhas com um contador e pare quando atingir N.

Ver solução
#include <stdio.h>
#include <stdlib.h>

int main(int argc, char *argv[]) {
    if (argc < 2) {
        fprintf(stderr, "uso: %s <n>\n", argv[0]);
        return 1;
    }

    int n = atoi(argv[1]);
    if (n <= 0) {
        fprintf(stderr, "n deve ser positivo\n");
        return 1;
    }

    char buf[512];
    int linhas = 0;
    while (linhas < n && fgets(buf, sizeof buf, stdin)) {
        printf("%s", buf);
        linhas++;
    }

    return 0;
}

./ex11_4 — com N=2 e o notas.txt imprime as duas primeiras linhas.

Nível Avançado

Exercício 3.11.5

Implemente um wc-lite: conte linhas, palavras e caracteres da stdin e imprima no formato "linhas palavras caracteres". Teste duas vezes: redirecionando o arquivo e via pipe.

Dica: Conte \n para linhas; para palavras, detecte transições de nao-espaco para espaco. "Caracteres" são todos os chars lidos.

Ver solução
#include <stdio.h>

int main(void) {
    long linhas = 0, palavras = 0, chars = 0;
    int em_palavra = 0;
    int c;

    while ((c = getchar()) != EOF) {
        chars++;
        if (c == '\n') linhas++;
        if (c == ' ' || c == '\n' || c == '\t') {
            em_palavra = 0;
        } else if (!em_palavra) {
            em_palavra = 1;
            palavras++;
        }
    }

    printf("%ld %ld %ld\n", linhas, palavras, chars);
    return 0;
}

./ex11_5 — com as 4 linhas do notas.txt via pipe (Get-Content notas.txt | .\ex11_5.exe) imprime "4 10 64": 4 linhas, 10 palavras, 64 caracteres (os 60 das palavras mais as 4 quebras de linha). Redirecionando o arquivo direto, o total de caracteres muda por causa dos \r\n do Windows.

🏗️ Miniprojeto: Seu mini-conjunto de utilitários

Empacote as ferramentas em um único programa "util.c" que interpreta a primeira palavra de argv como subcomando e executa: "grep palavra", "head N", "wc" e "reverse" sobre a stdin. Formato de saída igual ao dos exercícios. Imprima no stderr as mensagens de erro quando o subcomando não existir, e de uso quando faltar argumento; devolva 1 nesses casos e 0 no sucesso.

Critérios de aceite

  • Um único binário que lê o subcomando via strcmp sobre argv[1].
  • Implementa grep-lite, head-lite, wc-lite e reverse reutilizando as mesmas lógicas.
  • Trata caso de subcomando desconhecido com stderr + exit 1.
  • Trata ausência de argumento obrigatório (ex.: grep sem palavra) com uso + exit 1.
  • Cada subcomando devolve 0 em sucesso.
  • Testável com Get-Content notas.txt | .\util.exe grep caneta.
