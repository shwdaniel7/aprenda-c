const, ponteiro para const e const ponteiro

O qualificador const cria valores que não mudam — e o compilador vira seu fiscal. A posição da palavra muda tudo: const int *p = ponteiro para um int que não muda (o ponteiro pode apontar para outro lugar); int *const p = ponteiro fixo apontando para um int mutável; const int *const p = os dois fixos. Leia sempre do lado direito do *: o que está à esquerda do * é o tipo do dado apontado; o que está entre * e o nome é a "natureza" do ponteiro.

  • Tentou *p = x onde p é const int *? Erro de compilação.
  • Tentou p = &outra onde p é int *const? Erro de compilação.
  • Função que só lê um vetor deve receber const int v[]: promessa explícita ao chamador.
  • Cast para remover const (forçar o compilador) é código de cheiro — evite.
Código — const_ptr.c
#include <stdio.h>

int main(void)
{
    int a = 10, b = 20;
    const int *p1 = &a;   /* ponteiro para const: *p1 nao pode mudar */
    int *const p2 = &a;   /* const ponteiro: p2 nao pode apontar para outro */
    const int *const p3 = &a;

    p1 = &b;              /* ok: o ponteiro em si pode mudar */
    *p2 = 30;             /* ok: o int apontado pode mudar */
    /* *p1 = 99;   erro de compilacao: *p1 e const */
    /* p2 = &b;    erro de compilacao: p2 e const */

    printf("a=%d b=%d *p1=%d *p2=%d *p3=%d\n", a, b, *p1, *p2, *p3);
    return 0;
}
Saída esperada
> const_ptr
a=30 b=20 *p1=20 *p2=30 *p3=30

Lendo declarações complexas: da direita para a esquerda

Declarações como int (*pa)[4] assustam até você aplicar a regra: comece do nome e leia para a direita, dando a volta nos parênteses. pa é … leia a direita: nada → volta: *pa = pa é um ponteiro → para a direita: [4] = para um array de 4 → para a esquerda: de int. Logo, pa é "ponteiro para array de 4 int". Compare com int *arr[4]: arr é "array de 4 ponteiros para int". A diferença entre um e outro é feita só pelos parênteses.

Código — decl.c
#include <stdio.h>

int main(void)
{
    int arr[4] = {1, 2, 3, 4};
    int(*pa)[4] = &arr;   /* leia: pa e "ponteiro para array de 4 int" */
    for (int i = 0; i < 4; i++) {
        printf("%d ", (*pa)[i]);
    }
    putchar('\n');
    return 0;
}
Saída esperada
> decl
1 2 3 4

storage classes: extern, static, register, auto, _Thread_local

As storage classes controlam onde a variável mora e o tempo de vida. auto é o padrão (variável local de função, soma e some). register é uma dica esquecida (o compilador decide). static em escopo local dá à variável "memória de longo prazo" entre chamadas; em escopo de arquivo, limita a visibilidade ao arquivo. extern declara algo definido em outro arquivo: o link é feito na fase de linkagem. _Thread_local (C11) cria uma cópia por thread — veremos threads no módulo 06. A melhor pergunta para escolher é sempre: o que deve acontecer com essa variável quando a função termina?

  • static int contador = 100; dentro de função → persiste entre chamadas.
  • static no topo do arquivo → chave "privada" daquele .c.
  • extern int global; → "existe em outro arquivo, me deixa usar aqui".
  • register é histórico; com otimizadores modernos é inócuo.
  • _Thread_local → uma instância por thread (C11).
Código — stor.c
#include <stdio.h>

static int chamadas = 0;   /* static em escopo de arquivo: visivel so neste .c */

static int proximo_id(void)
{
    static int contador = 100;   /* static local: persiste entre chamadas */
    chamadas++;
    return contador++;
}

int main(void)
{
    for (int i = 0; i < 5; i++) {
        printf("id %d\n", proximo_id());
    }
    printf("chamadas = %d\n", chamadas);
    return 0;
}
Saída esperada
> stor
id 100
id 101
id 102
id 103
id 104
chamadas = 5

typedef com structs e tipos incompletos

typedef cria apelidos. Combinado com struct, elimina a repetição da palavra struct. A técnica do tipo incompleto é o coração das listas encadeadas: typedef struct No No; anuncia o nome antes do corpo; dentro do próprio struct usamos No *prox (ponteiro, que não precisa do corpo completo). O corpo completo só precisa existir quando o compilador precisar do tamanho do struct. É assim que structs se referenciam.

Código — no.c
#include <stdio.h>

typedef struct No {
    int valor;
    struct No *proximo;
} No;

int main(void)
{
    No a = {1, NULL};
    No b = {2, NULL};
    No c = {3, NULL};
    a.proximo = &b;
    b.proximo = &c;
    for (No *p = &a; p != NULL; p = p->proximo) {
        printf("%d ", p->valor);
    }
    putchar('\n');
    return 0;
}
Saída esperada
> no
1 2 3

volatile: quando o valor muda sem o código saber

Um int normal pode ser mantido pelo compilador num registro por otimização — tudo bem, porque nenhum código externo o altera. volatile diz ao compilador: "não confie na sua cópia; releia da memória toda vez". É usado quando o valor muda por fatores fora do fluxo do programa: registradores de hardware (chips), memória compartilhada entre processos, ou variáveis modificadas por interrupções/sinais (que veremos no módulo 05). Sem volatile, o otimizador pode "cachear" a variável e nunca perceber a mudança.

  • volatile int registrador; — aponta para um registrador de um periférico.
  • volatile sig_atomic_t flag — comunicando com um handler de sinal.
  • Sem volatile, um loop while (flag) {} compilado em -O2 pode virar loop infinito real.
  • volatile não é atômico: impede otimização, não corrida entre threads (ver módulo 07).

Nível 1

Exercício 3.03.1

Uma função imprime(const int v[], size_t n) que apenas lê o vetor deve aceitar tanto um array normal quanto um literal (int[]){7, 8}. Escreva a função e um main que a chama com nums[] e com o literal. Depois tente const int *p = nums; p[0] = 9; e observe o erro do compilador.

Dica: O nome do array "decai" para um ponteiro para o primeiro elemento; com const no parâmetro, a escrita vira erro garantido.

Ver solução
#include <stdio.h>

static void imprime(const int v[], size_t n)
{
    for (size_t i = 0; i < n; i++) {
        printf("%d ", v[i]);
    }
    putchar('\n');
}

int main(void)
{
    int nums[] = {5, 10, 15};
    const int *p = nums;   /* posso ler atraves de p, mas nao escrever */
    /* p[0] = 9;   erro: elemento e const */
    printf("leitura via const ponteiro: %d\n", *p);
    imprime(nums, 3);
    imprime((int[]){7, 8}, 2);
    return 0;
}

Saída real: "leitura via const ponteiro: 5", depois "5 10 15" e "7 8". Remova o comentário na linha proibida e veja o gcc reclamar.

Nível 2

Exercício 3.03.2

Crie um typedef typedef int (*operacao)(int, int); e implemente soma, multiplica e maior. Monte um array operacao ops[] = {soma, multiplica, maior} e chame cada uma com (6, 7) num loop.

Dica: array de operação: ops[i](6, 7). Um array de vetor de ponteiros de função é "array de ponteiros para função que recebe 2 int e devolve int".

Ver solução
#include <stdio.h>

typedef int (*operacao)(int, int);

static int soma(int a, int b)
{
    return a + b;
}

static int multiplica(int a, int b)
{
    return a * b;
}

static int maior(int a, int b)
{
    return a > b ? a : b;
}

int main(void)
{
    operacao ops[] = {soma, multiplica, maior};
    const char *nomes[] = {"soma", "multiplica", "maior"};
    int a = 6, b = 7;
    for (size_t i = 0; i < sizeof ops / sizeof ops[0]; i++) {
        printf("%s(%d, %d) = %d\n", nomes[i], a, b, ops[i](a, b));
    }
    return 0;
}

Saída real: soma=13, multiplica=42, maior=7. Esse padrão é o motor de "tabelas de operações".

Nível 3

Exercício 3.03.3

Implemente uma lista encadeada simples usando o padrão de tipo incompleto: typedef struct No No; no topo, corpo depois, funções insere (no início, com malloc) e conta. No main, insira 30, 20, 10 e imprima o total de nós.

Dica: O `typedef struct No No;` permite escrever No *prox dentro do próprio struct. Lembre de free() em todos os nós no final.

Ver solução
#include <stdio.h>
#include <stdlib.h>

typedef struct No No;   /* incomplete type: so o "nome" chamado */

struct No {
    int valor;
    No *prox;
};

static No *insere(No *lista, int v)
{
    No *n = malloc(sizeof *n);
    if (n != NULL) {
        n->valor = v;
        n->prox = lista;
    }
    return n;
}

static int conta(No *lista)
{
    int c = 0;
    for (No *p = lista; p != NULL; p = p->prox) {
        c++;
    }
    return c;
}

int main(void)
{
    No *lista = NULL;
    lista = insere(lista, 30);
    lista = insere(lista, 20);
    lista = insere(lista, 10);
    printf("nos = %d\n", conta(lista));
    while (lista != NULL) {
        No *tmp = lista;
        lista = lista->prox;
        free(tmp);
    }
    return 0;
}

Saída real: "nos = 3". Inserir na frente é O(1) — é por isso que `prox` precisa ser um ponteiro.
