Biblioteca padrão e tratamento de erros

stdlib, errno, exit status, atexit e assert

Nível: Avançado Duração: ~35 min Pré-requisitos: T2.10 (funções), T2.11 (strings), T2.13 (arquivos)

🎯 Objetivos

Conhecer o mapa da biblioteca padrão do C e adotar a postura de quem programa "à prova de erros": retornar status de saída explícitos, validar conversões com strtol, descobrir a causa de uma falha com errno/perror/strerror, agendar limpeza com atexit e usar assert como trava de desenvolvimento.

Um mapa da biblioteca padrão

A biblioteca padrão do C é o conjunto de funções e macros que acompanham qualquer compilador. Ela não é parte da "linguagem" (sintaxe), mas sem ela não existe programa prático. Você já usa várias; aqui está o mapa para quem quer enxergar o todo:

  • <stdio.h> — entrada/saída padrão: printf, fopen, fgets, fwrite.
  • <stdlib.h> — utilitários gerais: malloc/free, strtol, atoi, exit, atexit, qsort.
  • <string.h> — manipulação de strings e memória: strcpy, strlen, memcpy, strtok.
  • <math.h> — funções matemáticas: sqrt, pow, floor, isfinite.
  • <time.h> — tempo e datas: time, clock, difftime.
  • <ctype.h> — classificação de caracteres: isalpha, isdigit, toupper.
  • <limits.h> e <float.h> — faixas e precisão dos tipos (INT_MAX, DBL_EPSILON...).
  • <errno.h> — a variável global errno para reportar o último erro da libc.
  • <assert.h> — a macro assert para validações em tempo de desenvolvimento.

Aberturas de arquivo com verificação completa

O erro mais comum de quem começa é ignorar o retorno de fopen. Quando o arquivo não existe, fopen devolve NULL e o motivo fica na variável global errno (um número inteiro). strerror(errno) converte esse número numa mensagem legível; perror("texto") imprime o texto seguido de dois-pontos e da mensagem. Depois do loop de leitura, ferror(fp) detecta erros de I/O que não apareceram durante a leitura.

  • Sempre verifique o retorno de fopen antes de usar o ponteiro.
  • No loop, prefira fgets e teste ferror ao final (sair do loop não significa sucesso).
  • Use EXIT_FAILURE para falhas e EXIT_SUCCESS no fim normal (definidos em <stdlib.h>).
Código — abre.c
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <string.h>

int main(int argc, char **argv)
{
    if (argc != 2) {
        fprintf(stderr, "uso: %s <arquivo>\n", argv[0]);
        return EXIT_FAILURE;
    }
    FILE *fp = fopen(argv[1], "r");
    if (fp == NULL) {
        fprintf(stderr, "fopen: %s\n", strerror(errno));
        return EXIT_FAILURE;
    }
    char linha[256];
    unsigned num_linhas = 0;
    while (fgets(linha, sizeof linha, fp) != NULL) {
        num_linhas++;
    }
    if (ferror(fp)) {
        fprintf(stderr, "leitura: %s\n", strerror(errno));
        fclose(fp);
        return EXIT_FAILURE;
    }
    printf("%s tem %u linhas\n", argv[1], num_linhas);
    fclose(fp);
    return EXIT_SUCCESS;
}
Saída esperada
> abre nao_existe.txt
fopen: No such file or directory     (sai com EXIT_FAILURE)

> abre numeros.txt    (arquivo com 1.5, 2.5 e 3.0, uma por linha)
numeros.txt tem 3 linhas

Validando conversão de texto para número com strtol

strtol (e o irmão de 64 bits strtoll) é a forma correta de converter texto em inteiro — muito superior a atoi, que não sinaliza erro nenhum. Ela devolve o número e usa três canais para reportar problema: errno (fica ERANGE se o valor estourar a faixa), o ponteiro endptr (aponta onde a conversão parou), e o retorno. Regras de ouro: zere errno antes; considere falha se endptr == nptr (nada foi convertido) ou se sobrarem caracteres (*endptr != '\0').

Código — divisor.c
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <limits.h>

int main(int argc, char **argv)
{
    if (argc != 3) {
        fprintf(stderr, "uso: %s <dividendo> <divisor>\n", argv[0]);
        return EXIT_FAILURE;
    }
    errno = 0;
    char *fim = NULL;
    long long a = strtoll(argv[1], &fim, 10);
    if (errno == ERANGE || fim == argv[1] || *fim != '\0') {
        fprintf(stderr, "dividendo invalido: %s\n", argv[1]);
        return EXIT_FAILURE;
    }
    errno = 0;
    fim = NULL;
    long long b = strtoll(argv[2], &fim, 10);
    if (errno == ERANGE || fim == argv[2] || *fim != '\0') {
        fprintf(stderr, "divisor invalido: %s\n", argv[2]);
        return EXIT_FAILURE;
    }
    if (b == 0) {
        fprintf(stderr, "divisao por zero\n");
        return EXIT_FAILURE;
    }
    if (a == LLONG_MIN && b == -1) {
        fprintf(stderr, "overflow: LLONG_MIN / -1\n");
        return EXIT_FAILURE;
    }
    printf("%lld / %lld = %lld (resto %lld)\n", a, b, a / b, a % b);
    return EXIT_SUCCESS;
}
Saída esperada
> divisor 100 8
100 / 8 = 12 (resto 4)

> divisor 100 0
divisao por zero

> divisor abc 5
dividendo invalido: abc

> divisor -9223372036854775808 -1
overflow: LLONG_MIN / -1

exit, exit status e atexit

A função main retornar um número (o exit status) é como o programa responde ao sistema operacional: 0 (ou EXIT_SUCCESS) significa sucesso; qualquer outro valor (convencionalmente EXIT_FAILURE = 1) significa falha. exit(n) encerra no meio do caminho executando a mesma limpeza do return de main; _Exit(n) encerra sem limpeza nenhuma. atexit(funcao) registra funções que rodam na saída — na ordem inversa do registro (LIFO).

Código — despedida.c
#include <stdio.h>
#include <stdlib.h>

static void limpar(void)
{
    printf("limpando recursos...\n");
}

static void despedida(void)
{
    printf("ate logo!\n");
}

int main(void)
{
    atexit(limpar);
    atexit(despedida);
    printf("corpo do programa\n");
    return 0;
}
Saída esperada
> despedida
corpo do programa
ate logo!
limpando recursos...

assert: a trava de desenvolvimento

A macro assert(expressao) aborta o programa com uma mensagem se a expressão for falsa — mas somente na compilação de desenvolvimento. É a forma barata de declarar pré-condições: "aqui, esta condição TEM que valer". No momento da release, você compila com -DNDEBUG e todas as asserções somem do executável (sem custo). Note a diferença: assert serve para bugs de lógica, não para erros de usuário (esses você trata com errno/if).

Código — fat.c
#include <stdio.h>
#include <assert.h>

static int fatorial(int n)
{
    assert(n >= 0 && n <= 12);
    int r = 1;
    for (int i = 2; i <= n; i++) {
        r *= i;
    }
    return r;
}

int main(void)
{
    printf("5! = %d\n", fatorial(5));
    printf("12! = %d\n", fatorial(12));
    return 0;
}
Saída esperada
> fat
5! = 120
12! = 479001600

✏️ Exercícios

Nível 1

Exercício 3.01.1

Escreva um programa que tenta abrir uma arquivo inexistente e mostra o erro de três formas: (1) imprimindo o valor cru de errno, (2) com perror, (3) com strerror(errno) dentro de um printf seu.

Dica: Lembre-se de incluir <errno.h>. perror recebe um rótulo e já escreve na saída de erro.

Ver solução
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <string.h>

int main(void)
{
    FILE *fp = fopen("arquivo_que_nao_existe.txt", "r");
    if (fp == NULL) {
        printf("errno = %d\n", errno);
        perror("perror diz");
        printf("strerror diz: %s\n", strerror(errno));
        printf("mensagem propria: nao consegui abrir o arquivo\n");
        return EXIT_FAILURE;
    }
    fclose(fp);
    return EXIT_SUCCESS;
}

No Windows (MinGW) a mensagem vem em inglês — "No such file or directory". O número errno 2 é ENOENT. Em scripts você compara com as constantes, nunca com números mágicos.

Nível 2

Exercício 3.01.2

Crie uma função media(const double v[], size_t n) que tem assert(n > 0). Compile e rode sem flags; depois compile com -DNDEBUG e rode de novo, observando o que muda quando a pré-condição é violada chame media com um vetor vazio.

Dica: No teste, chame media com n == 0 de propósito. Com assert ativo o programa aborta; com NDEBUG ele segue e faz divisão por zero.

Ver solução
#include <stdio.h>
#include <assert.h>

static double media(const double v[], size_t n)
{
    assert(n > 0);
    double soma = 0.0;
    for (size_t i = 0; i < n; i++) {
        soma += v[i];
    }
    return soma / (double)n;
}

int main(void)
{
    setvbuf(stdout, NULL, _IONBF, 0);   /* saia de vez (sem buffer) antes do abort */
    printf("media = %.2f\n", media((double[]){10.0, 20.0, 30.0}, 3));
    printf("media vazia = %.2f\n", media((double[]){5.0}, 0));
    return 0;
}

Saída com assert ativo: "media = 20.00" seguida de "Assertion failed: n > 0". Com -DNDEBUG: "media = 20.00" e "media vazia = -nan(ind)" (0.0/0.0). Isso é o assert na prática: ele pega o bug antes dele virar comportamento estranho.

Nível 3

Exercício 3.01.3

Implemente um somador de linha de comando somaargs 10 20 30 que soma todos os argumentos (de long long). Cada argumento deve ser validado com strtoll (ERANGE, sem conversão, sobra de caracteres) e a soma deve detectar overflow antes de somar, usando LLONG_MAX/LLONG_MIN.

Dica: A soma estoura se (v > 0 && soma > LLONG_MAX - v) ou (v < 0 && soma < LLONG_MIN - v). Isso evita que a soma sequer chegue a estourar.

Ver solução
#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <limits.h>

int main(int argc, char **argv)
{
    long long soma = 0;
    for (int i = 1; i < argc; i++) {
        errno = 0;
        char *fim = NULL;
        long long v = strtoll(argv[i], &fim, 10);
        if (errno == ERANGE || fim == argv[i] || *fim != '\0') {
            fprintf(stderr, "argumento %d invalido: %s\n", i, argv[i]);
            return EXIT_FAILURE;
        }
        if ((v > 0 && soma > LLONG_MAX - v) ||
            (v < 0 && soma < LLONG_MIN - v)) {
            fprintf(stderr, "overflow da soma\n");
            return EXIT_FAILURE;
        }
        soma += v;
    }
    printf("soma = %lld\n", soma);
    return EXIT_SUCCESS;
}

Observe a saída real: somaargs 10 20 30 imprime "soma = 60"; somaargs 9223372036854775807 5 imprime "overflow da soma"; somaargs 1 dois imprime "argumento 2 invalido".

❓ Verificação rápida

🏗️ Miniprojeto: wc-lite: contador de linhas, palavras e bytes

Crie um utilitário tipo o wc do Linux: wclite arquivo.txt imprime o número de linhas, de palavras (separadas por espaço/tab/nova linha) e de bytes do arquivo. Trate TODOS os erros: argumento ausente (uso), arquivo inexistente (strerror), erro no meio da leitura (ferror). Use EXIT_SUCCESS/EXIT_FAILURE corretamente e registre um atexit que imprime o tempo total gasto.

Critérios de aceite

  • Compila sem avisos com gcc -Wall -Wextra -std=c11.
  • Sem o argumento de arquivo, mostra a mensagem de uso e retorna EXIT_FAILURE.
  • Arquivo inexistente: mensagem com strerror(errno) e EXIT_FAILURE.
  • Relatório correto de linhas/palavras/bytes para um arquivo de teste com 3 linhas.
  • Saída final ordenada (não embaralhada) quando você o redireciona para um arquivo.
