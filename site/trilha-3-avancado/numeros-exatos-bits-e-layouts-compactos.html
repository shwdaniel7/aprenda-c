Números exatos, bits e layouts compactos

Inteiros de largura fixa, bit-fields e membros flexíveis: controle preciso da memória para protocolos e formatos binários.

Nível: Avançado Duração: ~45 min Pré-requisitos: Conhecer structs e unions (T2.06, T2.07). Entender representação binária e hexa (T3.02).

🎯 Objetivos

Dominar os tipos inteiros de largura exata de e , usar bit-fields para empacotar flags e cabeçalhos compactos, empregar union e compound literals em código expressivo, aplicar complemento de 2 com segurança e montar estruturas de tamanho previsível — o pão-de-açúcar de protocolos de rede e de arquivos binários.

Inteiros de largura exata: <stdint.h> e <inttypes.h>

O C tradicional manda int ter "pelo menos 16 bits" — e cada plataforma interpreta como quer. Inútil para dados binários que precisam ter o mesmo formato em qualquer máquina (arquivos, protocolos). A solução é <stdint.h>, que define, quando a plataforma oferece, tipos de largura exata: uint8_t, uint16_t, uint32_t, uint64_t e suas versões com sinal.

Por que uint8_t em vez de unsigned char para um byte? Porque o nome documenta a intenção e o tamanho fica garantido. E por que não usar long long direto? Porque até ele tem largura oficialmente só "pelo menos 64 bits" — na prática é 64, mas a especificação do tipo exato remove a ambiguidade.

No exemplo, veja também o hexa com %x e %llx, e o complemento de 2: o (uint32_t)a com a = -123456 vira 0xFFFE1DC0 — os 32 bits do número negativo reinterpretados sem sinal.

  • <stdint.h> — define uint8_t, uint16_t, uint32_t, uint64_t e os com sinal, sempre que a plataforma os tiver.
  • <inttypes.h> — macros de formato: PRIu32, PRIu64, PRIx64, SCNd32...
  • Complemento de 2: um int negativo, reinterpretado como uint32_t, vira o padrão de bits correto (ex.: -123456 = 0xFFFE1DC0).
  • sizeof(uint32_t) == 4, sizeof(uint64_t) == 8 — sempre.
Código — t3m1001
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {
    int a = -123456;
    uint32_t b = 0xCAFEBABE;
    uint64_t c = 123456789012345ULL;
    uint64_t d = UINT64_MAX;

    printf("a       = %d (padrao de bits %08x)\n", a, (unsigned int)(uint32_t)a);
    printf("b       = %" PRIu32 " (hexa 0x%08" PRIx32 ")\n", b, b);
    printf("c       = %" PRIu64 "\n", c);
    printf("d (max) = %" PRIu64 " (hexa 0x%" PRIx64 ")\n", d, d);
    printf("sizeof: uint32_t = %zu, uint64_t = %zu\n",
           sizeof(uint32_t), sizeof(uint64_t));

    return 0;
}

Asserções e limites exatos

Quando o programa precisa de garantias de tamanho (um protocolo exige 4 bytes para um campo), o profissional não confia em suposições: ele verifica em tempo de compilação com _Static_assert (C11) ou em tempo de execução com assert. As duas têm o mesmo espírito: a falha é detectada o mais cedo possível.

_Static_assert recebe uma expressão constante e uma mensagem; se a condição for falsa, o compilador se recusa a gerar o binário. É ideal para tamanhos de struct que vão para disco ou rede.

No exemplo, garantimos que o código só compila se CHAR_BIT == 8 e sizeof(uint32_t) == 4, e com assert conferimos limites de <limits.h> e <stdint.h>.

  • _Static_assert(cond, "mensagem") — falha no compilador se a condição (constante) for falsa.
  • assert(expr) — aborta em execução (com mensagem) se a expressão for falsa; some com NDEBUG.
  • CHAR_BIT, UINT_MAX (em <limits.h>) e UINT16_MAX, UINT32_MAX (em <stdint.h>).
  • Quando uma struct precisa de layout exato (ex.: 4 bytes), use _Static_assert(sizeof(struct X) == 4).
Código — t3m1002
#include <stdio.h>
#include <stdint.h>
#include <limits.h>
#include <assert.h>

_Static_assert(CHAR_BIT == 8, "este programa exige bytes de 8 bits");
_Static_assert(sizeof(uint32_t) == 4, "uint32_t precisa ter 4 bytes");

int main(void) {
    assert(UINT16_MAX >= 65535);
    assert(UINT32_MAX >= 4294967295U);
    assert(sizeof(int) >= 4);

    printf("todas as assercoes passaram\n");
    printf("CHAR_BIT=%d sizeof(int)=%zu sizeof(uint16_t)=%zu\n",
           CHAR_BIT, sizeof(int), sizeof(uint16_t));

    return 0;
}
Saída esperada
> .static-assert.exe
> todas as assercoes passaram
> CHAR_BIT=8 sizeof(int)=4 sizeof(uint16_t)=2

Bit-fields: flags e campos de N bits

Nem todo dado precisa de 32 (ou 8) bits. Uma flag ligado/desligado precisa de 1. Um dia da semana, de 3. Para empacotar vários campos pequenos na mesma memória, o C oferece os bit-fields: membros de struct declarados como unsigned tipo : N;.

O compilador empacota os campos em unidades de armazenamento (aqui, 4 bytes — o unsigned base). O tamanho total do struct no exemplo é 8 bytes porque o alinhamento atua junto; para protocolos com layout rígido, verifique com _Static_assert e, se preciso, reordene os campos ou use _Alignas.

Para gravar num arquivo binário, imprimimos o struct byte a byte como unsigned char — é assim que se serializa de forma portável: o padding entre campos é definido pelo compilador, então empacote seus bit-fields dentro de um uint32_t/uint64_t para formatos fixos.

  • Bit-field: unsigned vermelho : 1; — reserva exatamente N bits.
  • O tipo base (unsigned, int de implementação, ou os exatos) determina a unidade de armazenamento.
  • Campos de 1 bit são perfeitos para flags: leitura = 1, escrita = 1, etc.
  • Previsibilidade de layout: o padding é definido pela implementação; para formato de arquivo, serialize bit a bit ou use _Static_assert.
Código — t3m1003
#include <stdio.h>
#include <stdint.h>

struct Flags {
    unsigned leitura   : 1;
    unsigned escrita   : 1;
    unsigned execucao  : 1;
    unsigned reservado : 5;
    unsigned extensao  : 5;
    unsigned fds       : 1;
    unsigned seg       : 1;
    unsigned exts      : 5;
    unsigned exto      : 5;

};

int main(void) {
    struct Flags f = {0};
    f.leitura = 1;
    f.escrita = 0;
    f.execucao = 1;
    f.seg = 0;

    printf("leitura=%u escrita=%u execucao=%u seg=%u exts=%u exto=%u\n",
           f.leitura, f.escrita, f.execucao, f.seg, f.exts, f.exto);
    printf("sizeof(struct Flags) = %zu bytes\n", sizeof f);

    unsigned char *b = (unsigned char *)&f;
    printf("bytes: ");
    for (size_t i = 0; i < sizeof f; i++) {
        printf("%02x ", b[i]);
    }
    printf("\n");

    return 0;
}

Union: um tipo, vários significados

Uma union faz todos os seus membros ocuparem o mesmo endereço. O tamanho da union é o do maior membro (mais o alinhamento). É a ferramenta certa para dizer "este espaço tem dois significados possíveis", como um valor que ora é inteiro, ora é a união de dois inteiros menores.

No exemplo, temos um dado de 8 bytes que pode ser lido como um uint64_t ou como um par de floats. Escrevemos pela visão de bytes e lemos pelas duas outras visões — e o mesmo bloco de memória responde às duas leituras.

O perigo clássico é ler por um membro que você não escreveu. Aí o comportamento é definido pela implementação (daí a recomendação de gravar e ler sempre pelo mesmo campo, ou guardar num campo "tag" qual visão está ativa — ver projeto do módulo).

  • union { A; B; } — membros compartilham o mesmo endereço.
  • sizeof(union) = tamanho do maior membro (alinhado).
  • Útil também para reinterpretar bytes: escreva com uint8_t, leia como uint16_t/uint32_t, respeitando o endianness.
  • A union não "memoriza" qual membro foi usado: mantenha a disciplina de controle no seu código.
Código — t3m1004
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

union Valor {
    uint64_t bits;
    float reais[2];
};

int main(void) {
    union Valor v;

    v.bits = 0;
    v.reais[0] = 10.5f;
    v.reais[1] = 20.0f;

    v.bits = 0xFFFFFFFFC0800000ULL;
    v.reais[1] = -3.25f;

    printf("[0]=%.2f [1]=%.2f\n", v.reais[0], v.reais[1]);
    printf("sizeof(union Valor) = %zu\n", sizeof v);
    printf("bits = 0x%016" PRIx64 "\n", v.bits);

    struct { union Valor x; } emb;
    emb.x = v;
    printf("total membros: %zu bytes\n", sizeof emb);

    return 0;
}

Compound literals e variáveis temporárias

Às vezes você precisa passar para uma função um valor composto — um struct, um vetor — sem criar uma variável nomeada antes. Os compound literals (C99) fazem exatamente isso: (struct Ponto){ x, y } é um valor temporário de tipo struct Ponto.

Eles valem também para vetores: (int[]){1,2,3}, e até para union: (union X){ .campo = v }. Em Portugol você não tem isso; em C, é uma das formas mais legíveis de montar argumentos compostos.

No exemplo, somamos dois pontos construídos literalmente e aplicamos uma "transformação" que também recebe um literal. Resultado: 34 / 15, e o deslocamento empilhado vira o ponto (101, -49) — sem nenhuma variável intermediária nomeada.

  • (struct Tipo){ a, b } — literal composto de struct no meio da expressão.
  • Também funciona com vetores: (int[]){1,2,3} e com union: (union U){ .membro = v }.
  • O literal composto tem armazenamento automático (vida até o fim do bloco) se usado dentro de função.
  • Ideal para chamar funções com argumentos compostos sem variáveis temporárias.
Código — t3m1005
#include <stdio.h>

struct Ponto { int x, y; };

struct Ponto soma(struct Ponto a, struct Ponto b) {
    struct Ponto r = { a.x + b.x, a.y + b.y };
    return r;
}

struct Ponto translada(struct Ponto p, struct Ponto delta) {
    struct Ponto r = { p.x + delta.x, p.y + delta.y };
    return r;
}

int main(void) {
    struct Ponto p1 = soma((struct Ponto){ 13, 7 }, (struct Ponto){ 21, 8 });
    printf("p1 = %d / %d\n", p1.x, p1.y);

    struct Ponto p2 = translada(p1, (struct Ponto){ -10, 5 });
    printf("p2 = %d / %d\n", p2.x, p2.y);

    struct Ponto p3 = translada(
        translada((struct Ponto){ 100, -50 }, (struct Ponto){ 2, 3 }),
        (struct Ponto){ -1, -2 });
    printf("p3 = %d / %d\n", p3.x, p3.y);

    return 0;
}
Saída esperada
> .compound-literals.exe
> p1 = 34 / 15
> p2 = 24 / 20
> p3 = 101 / -49

Lendo números exatos com SCNd32: erros reais

Entrada de dados confiável é um problema à parte: scanf devolve a quantidade de conversões feitas, e é obrigatório conferir. Com tipos exatos, o especificador de leitura vem de <inttypes.h>: SCNd32 para int32_t, SCNu16 para uint16_t, e assim por diante.

No exemplo, tentamos ler uma porta (número) da entrada padrão. Se vier "9000", tudo bem. Se vier texto puro ("abc"), o scanf falha na primeira conversão e devolvemos erro — sem crash, sem leitura lixo. Em modo parse de dados, essa checagem de retorno é a diferença entre um parser tolerante e um que aborta.

Repare que em sistemas Windows o % de SCNd32 com fgets como buffer é o máximo de robustez: primeiro lemos a linha inteira, depois tentamos o sscanf.

  • SCNd32, SCNu16 — especificadores de scanf para tipos exatos.
  • scanf/sscanf devolvem o nº de conversões; confira sempre.
  • Falha: entrada não numérica -> retorno menor que o esperado -> trate como erro.
  • Padrão robusto: fgets da linha, depois sscanf da linha lida.
Código — t3m1006
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {
    char linha[64];
    int32_t porta;

    if (!fgets(linha, sizeof linha, stdin)) {
        printf("sem entrada\n");
        return 1;
    }

    if (sscanf(linha, "%" SCNd32, &porta) == 1) {
        printf("ok: porta=%" PRId32 "\n", porta);
    } else {
        printf("erro durante o parse (codigo 3): valor nao numerico\n");
        return 3;
    }

    return 0;
}
Saída esperada
> .setjmp-uso.exe

> (com entrada "abc")

Exercício 3.10.1

Imprima o valor 0xDEADBEEF em decimal (como uint32_t), em hexa maiúsculo, o mesmo valor reinterpretado como int32_t (em decimal), e o inteiro 42 em uint16_t, em decimal e em hexa com 4 dígitos. Imprima também os sizeof de cada tipo usado.

#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {

    uint16_t z = 42;

    printf("x decimal: %" PRIu32 "\n", x);
    printf("x hexa: 0x%" PRIX32 "\n", x);
    printf("y (int32): %" PRId32 "\n", y);
    printf("z: %" PRIu16 "\n", z);
    printf("z hexa: 0x%" PRIX16 "\n", z);
    printf("sizeof: uint32=%zu int32=%zu uint16=%zu\n",
           sizeof(uint32_t), sizeof(int32_t), sizeof(uint16_t));

Exercício 3.10.2

Crie uma struct Permissao com bit-fields para leitura, escrita e execução (1 bit cada) mais 5 bits de reserva, tudo sobre unsigned. Ative leitura e execução, imprima os três valores e o sizeof. Bytes printados com %%02x.

Dica: Declare unsigned leitura : 1; unsigned escrita : 1; unsigned execucao : 1; unsigned reservado : 5;. O struct (4 bytes) guarda os bits; os valores aparecem em 0/1.

Ver solução
#include <stdio.h>

struct Permissao {
    unsigned leitura   : 1;
    unsigned escrita   : 1;
    unsigned execucao  : 1;
    unsigned reservado : 5;
};

int main(void) {
    struct Permissao p = {0};
    p.leitura = 1;
    p.execucao = 1;

    printf("leitura=%u escrita=%u execucao=%u\n",
           p.leitura, p.escrita, p.execucao);
    printf("bits: ");
    unsigned char *b = (unsigned char *)&p;
    for (size_t i = 0; i < sizeof p; i++) {
        printf("%02x ", b[i]);
    }
    printf("\n");
    printf("sizeof=%zu\n", sizeof p);

    return 0;
}

Nível Avançado

Exercício 3.10.3

Crie uma struct Lista numerica com um membro flexível (fam), no padrão: cabeçalho (contagem) + vetor de ints no final. Escreva e leia valores, imprima os elementos e a soma, e imprima sizeof da struct (que deve ignorar o vetor flexível).

Dica: Declare struct Lista { size_t n; int itens[]; }; e aloque malloc(sizeof(struct Lista) + n * sizeof(int)).

Ver solução
#include <stdio.h>
#include <stdlib.h>

struct Lista {
    size_t n;
    int itens[];
};

int main(void) {
    const size_t n = 5;
    struct Lista *l = malloc(sizeof(struct Lista) + n * sizeof(int));
    if (!l) return 1;

    l->n = n;
    for (size_t i = 0; i < n; i++) {
        l->itens[i] = (int)(i * i);
    }

    printf("l:");
    long long soma = 0;
    for (size_t i = 0; i < l->n; i++) {
        printf(" %d", l->itens[i]);
        soma += l->itens[i];
    }
    printf("\n");
    printf("soma: %lld\n", soma);
    printf("sizeof(struct Lista) = %zu\n", sizeof(struct Lista));

    free(l);
    return 0;
}

Exercício 3.10.4

Modele um mini sistema de votação: union Candidato com membros int votos e float taxa; um vetor fixo de 3 candidatos com votos 10, 0, 12. Atribua o total de votos e a taxa média ao campo designado e imprima o total dos gêneros? Não — imprima por candidato o campo ativo (votos) e o total geral.

Dica: Simplifique: mostre os votos lidos pelo campo votos, soma-os num uint64_t, e imprima o total. A union ilustra que o espaço pode ser lido de outra forma.

Ver solução
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

union Candidato {
    int votos;
    float taxa;
};

int main(void) {
    union Candidato c[3];
    c[0].votos = 10;
    c[1].votos = 0;
    c[2].votos = 12;

    printf("votos:");
    uint64_t total = 0;
    for (int i = 0; i < 3; i++) {
        printf(" %d", c[i].votos);
        total += (uint64_t)c[i].votos;
    }
    printf("\n");
    printf("total = %" PRIu64 "\n", total);
    printf("sizeof(union) = %zu\n", sizeof(union Candidato));

    return 0;
}

Exercício 3.10.5

Escreva um parser de uma porta e de um host da stdin (formato "host:porta"), usando uint16_t para a porta e SCNu16. Em caso de entrada inválida, devolva o código de erro 3 e imprima "erro: valor nao numerico". No sucesso imprima "ok:" com host e porta.

Dica: Use fgets + sscanf com "%" SCNu16; verifique o retorno == 1 (host aceite como string qualquer).

Ver solução
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {
    char linha[128];
    char host[64];
    uint16_t porta;

    if (!fgets(linha, sizeof linha, stdin)) {
        printf("sem entrada\n");
        return 1;
    }

    if (sscanf(linha, "%63[^:]" ":%" SCNu16, host, &porta) == 2) {
        printf("ok: %s:%" PRIu16 "\n", host, porta);
    } else {
        printf("erro: valor nao numerico\n");
        return 3;
    }

    return 0;
}

🏗️ Miniprojeto: Cabeçalho de protocolo compacto

Implemente um cabeçalho de protocolo binário com bit-fields: um registro com 3 flags (1 bit), um campo de tipo (3 bits) e um campo de tamanho (4 bits), mais um campo payload de até 2 bytes, totalizando 1 byte de cabeçalho + payload. Grava esse registro em um arquivo binário "pacote.bin" e depois lê de volta, imprimindo todos os campos e o tamanho total (deve ser 1 byte de cabeçalho + payload, struct com _Static_assert de que o cabeçalho ocupa 1 byte se possível).

Critérios de aceite

  • 3 flags de 1 bit (fim_de_stream, urgente, crc_incluido).
  • Campo de tipo com 3 bits e campo de tamanho com 4 bits.
  • Cabeçalho em 1 byte (uint8_t contendo os 8 bits).
  • Grava em binário e lê de volta com memcpy.
  • Imprime os campos e o total de bytes.
  • Compila com gcc -Wall -Wextra -std=c11 sem avisos.
