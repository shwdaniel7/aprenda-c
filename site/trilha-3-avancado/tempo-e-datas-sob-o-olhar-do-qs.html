Tempo e datas (sob o olhar do QS)

Do epoch ao relógio de parede: como medir, carimbar e formatar tempo em C com padrão C11.

Nível: Avançado Duração: ~45 min Pré-requisitos: Conhecer ponteiros, structs e manipulação de strings (T2.06). Saber tratar erros de forma robusta (T3.01).

🎯 Objetivos

Compreender o modelo de tempo da linguagem C (epoch, time_t, struct tm), usar as funções do cabeçalho para obter o instante atual, converter entre UTC e local, formatar e parsear datas, medir intervalo de parede, CPU e nanossegundos — e aplicar tudo isso num registro de log com carimbo de hora, o padrão de um Quality System.

O tempo na máquina: epoch, time_t e struct tm

O computador não "sente" o tempo como nós. Ele guarda um inteiro gigante: o número de segundos decorridos desde a epoch — a meia-noite UTC de 1º de janeiro de 1970. Em C, esse valor inteiro é o tipo time_t, retornado por time().

A outra metade da história é o struct tm: uma estrutura com campos legíveis (tm_year, tm_mon, tm_mday, tm_hour…), preenchida por localtime() (no fuso da máquina) ou gmtime() (em UTC). Cuidado com dois detalhes que derrubam iniciantes: tm_year conta anos desde 1900 e tm_mon começa em 0 (janeiro).

No exemplo, exibimos o epoch e os dois "rostos" legíveis do mesmo instante: o local e o UTC. Note como tm_year + 1900 e tm_mon + 1 precisam ser ajustados na hora de imprimir.

  • time_t — inteiro (normalmente) que representa segundos desde a epoch; as funções de data devolvem/consomem esse tipo.
  • time(&t) — grava o instante atual em t; pode retornar o valor diretamente também.
  • struct tm — campos tm_year (anos desde 1900), tm_mon (0–11), tm_mday (1–31), tm_hour, tm_min, tm_sec, tm_wday, tm_yday, tm_isdst.
  • localtime()/gmtime() — convertem time_t para struct tm no fuso local ou em UTC.
  • asctime() — devolve uma string fixa (e feia) com a data/hora; ctime() faz o mesmo direto do time_t.
Código — t3m0901
#include <stdio.h>
#include <time.h>

int main(void) {
    time_t agora = time(NULL);

    printf("epoch: %lld\n", (long long)agora);
    printf("em horas: %lld\n", (long long)(agora / 3600));
    printf("em dias: %lld\n", (long long)(agora / 86400));

    struct tm *local = localtime(&agora);
    struct tm *utc = gmtime(&agora);

    printf("local: %04d-%02d-%02d %02d:%02d:%02d\n",
           local->tm_year + 1900, local->tm_mon + 1, local->tm_mday,
           local->tm_hour, local->tm_min, local->tm_sec);
    printf("utc  : %04d-%02d-%02d %02d:%02d:%02d\n",
           utc->tm_year + 1900, utc->tm_mon + 1, utc->tm_mday,
           utc->tm_hour, utc->tm_min, utc->tm_sec);
    printf("dia do ano: %d (0 = 1 de janeiro)\n", local->tm_yday);

    return 0;
}

Medindo intervalos: relógio de parede com difftime()

Medir quanto tempo um trecho demorou parece trivial: pegue o instante antes, o instante depois e subtraia. O C11 padronizou isso com difftime(), que devolve a diferença em segundos (como double) entre dois instantes time_t.

O relógio do time() tem resolução de segundo, então para algo mais fino você precisará de outro recurso (veremos clock() e timespec_get() logo adiante). Para trechos longos, porém, a leitura em segundos inteiros é suficiente e é o que usamos aqui.

No exemplo, medimos quanto tempo o loop de soma demora. Para evitar que o otimizador "aposte" que o resultado não é usado e elimine o loop, imprimimos a soma ao final. Esse é um truque clássico de toda medição em C.

  • double difftime(time_t fim, time_t inicio) — devolve fim - inicio em segundos.
  • Cuidado com a ordem: primeiro capturamos o início, depois o fim.
  • Nunca declare o resultado de medição como int; use double (ou long long quando for epoch).
  • Se o tempo marcado for 0, verifique a resolução do relógio, não a "velocidade" do trecho.
Código — t3m0902
#include <stdio.h>
#include <time.h>

int main(void) {
    time_t inicio = time(NULL);

    long long soma = 0;
    for (long long i = 0; i < 200000000LL; i++) {
        soma += i;
    }

    time_t fim = time(NULL);
    double decorrido = difftime(fim, inicio);

    printf("soma: %lld\n", soma);
    printf("decorrido: %.0f s (parede)\n", decorrido);

    return 0;
}
Saída esperada
> .medindo-difftime.exe
> soma: 19999999900000000
> decorrido: 2 s (parede)
> 
> (Os segundos exatos variam conforme a máquina e a carga; na execução de referência, 2 s.)

clock() como cronômetro

Há uma diferença sutil mas importante entre relógio de parede e tempo de processador. O primeiro conta tudo (inclusive enquanto o processo dorme esperando I/O); o segundo conta só o tempo em que a CPU esteve executando o seu código.

A função clock() devolve clock_t, um valor em unidades de clock (ticks). Para converter em segundos, divide-se por CLOCKS_PER_SEC. O número de ticks por segundo não precisa ser 1.000.000 — é o sistema que define —, mas a divisão sempre produz segundos.

Note que clock() é o recurso certo para comparar a performance de duas implementações do mesmo algoritmo no mesmo processo. O relógio de parede incluiria qualquer balanço do sistema operacional.

  • clock_t clock(void) — tempo de CPU consumido pelo processo, em ticks.
  • CLOCKS_PER_SEC — quantos ticks há em um segundo; divida para obter segundos.
  • Sempre converta com cast para double antes de dividir (evite truncamento).
  • Não use clock() para carimbar data/hora: ele não tem relação com a epoch.
Código — t3m0903
#include <stdio.h>
#include <time.h>

int main(void) {
    clock_t inicio = clock();

    long long soma = 0;
    for (long long i = 0; i < 300000000LL; i++) {
        soma += i;
    }

    clock_t fim = clock();
    double segundos = (double)(fim - inicio) / CLOCKS_PER_SEC;

    printf("soma: %lld\n", soma);
    printf("cpu: %.3f s\n", segundos);

    return 0;
}
Saída esperada
> .cronometro-clock.exe
> soma: 44999999985000000
> cpu: 0.132 s
> 
> (O tempo de CPU varia conforme a máquina; na execução de referência, 0.132 s.)

Convertendo e construindo datas: mktime()

Até aqui só "descemos" do epoch para o calendário. O caminho inverso é o mktime(): recebe um struct tm (no fuso local) e devolve o time_t correspondente. É ele que permite transformar uma data digitada em epoch.

Uma surpresa útil: o mktime() normaliza os campos. Se você montar 40 de março, ele entende que isso é 9 de abril e ajusta tm_mday/tm_mon na própria estrutura — corrigindo automaticamente "estouros" de calendário.

No exemplo, além de mostrar o epoch de uma data fixa (15/06/2000), demonstramos a normalização: montamos 40/03/2000 e deixamos o mktime resolver. Em sistemas com resolução de 1 s, o horário é assumido meia-noite local.

  • mktime(struct tm *) — devolve time_t; se a data for inválida, devolve (time_t)-1.
  • Normalização: valores fora de faixa (mês 13, dia 40) são convertidos automaticamente.
  • tm_isdst — se -1, o horário de verão é descoberto automaticamente.
  • O epoch é sempre interpretado como hora local pela mktime; para UTC você precisaria ajustar o fuso manualmente.
Código — t3m0904
#include <stdio.h>
#include <time.h>

int main(void) {
    time_t agora = time(NULL);
    printf("epoch agora: %lld\n", (long long)agora);

    struct tm *local = localtime(&agora);
    printf("agora local: %04d-%02d-%02d %02d:%02d:%02d\n",
           local->tm_year + 1900, local->tm_mon + 1, local->tm_mday,
           local->tm_hour, local->tm_min, local->tm_sec);

    struct tm nasc = {0};
    nasc.tm_year = 2000 - 1900;
    nasc.tm_mon = 5;
    nasc.tm_mday = 15;
    time_t t = mktime(&nasc);
    printf("15/06/2000 -> epoch %lld\n", (long long)t);

    struct tm mud = {0};
    mud.tm_year = 2000 - 1900;
    mud.tm_mon = 2;
    mud.tm_mday = 40;
    time_t t2 = mktime(&mud);
    printf("40 de marco -> vira %02d/%02d/%04d, epoch %lld\n",
           mud.tm_mday, mud.tm_mon + 1, mud.tm_year + 1900, (long long)t2);

    return 0;
}

Formatando datas: strftime()

Imprimir datas na mão, campo a campo, funciona — mas é frágil e verboso. O padrão C oferece strftime(): você passa um buffer, seu tamanho, uma máscara com especificadores e um struct tm; a função preenche o buffer, devolvendo quantos caracteres escreveu.

Os especificadores lembram printf, mas com % próprios: %Y ano com 4 dígitos, %m mês 2 dígitos, %d dia, %H:%M:%S hora, %j dia do ano, %A nome do dia da semana. Basta concatená-los para montar o formato que o seu sistema (o Quality System do seu time, por exemplo) exigir.

Sempre confira o retorno: se for igual ao tamanho do buffer, o espaço era insuficiente e a string foi truncada (ou nada escrito) — um erro clássico em relatórios de produção.

  • `strftime(buf, tam, formato, tm)` — escreve em buf, devolve o nº de caracteres ou 0.
  • Especificadores comuns: %Y, %m, %d, %H, %M, %S, %j, %A, %a, %B.
  • %Y-%m-%d %H:%M:%S é o formato ISO-8601, recomendado para logs.
  • Os caracteres que não começam com % (hífens, dois-pontos, espaços) são copiados literalmente.
Código — t3m0905
#include <stdio.h>
#include <time.h>

int main(void) {
    time_t agora = time(NULL);
    struct tm *local = localtime(&agora);

    char buf[128];

    strftime(buf, sizeof buf, "%d/%m/%Y", local);
    printf("data curta: %s\n", buf);

    strftime(buf, sizeof buf, "%Y-%m-%d", local);
    printf("iso: %s\n", buf);

    strftime(buf, sizeof buf, "%A, dia %d de %B de %Y", local);
    printf("por extenso: %s\n", buf);

    strftime(buf, sizeof buf, "[%Y-%m-%d %H:%M:%S]", local);
    printf("formato de log: %s\n", buf);

    char hora[16];
    strftime(hora, sizeof hora, "%H:%M:%S", local);
    printf("hora: %s\n", hora);

    return 0;
}

> formato de log: [2026-09-15 17:17:49]

Nanossegundos e o relógio monotônico: timespec_get()

Precisão de 1 segundo não basta para medir funções rápidas — e o C11 trouxe a resposta: timespec_get(), que preenche um struct timespec com segundos (campo tv_sec) e nanossegundos (campo tv_nsec). No Windows/glibc atuais ela é implementada sobre relógio de alta resolução.

A constante a passar é TIME_UTC: o relógio tem base na epoch (UTC). Combinando os dois campos, você consegue timestamps como 1789503469.243354400 — carimbo completo, ideal para eventos de alta frequência.

Para medir trechos curtos, capture o timespec antes e depois e subtraia campo a campo, tomando cuidado com o "empréstimo" dos nanossegundos (se tv_nsec_fim < tv_nsec_inicio, subtraia 1 do segundo e some 1e9 aos nanossegundos).

  • struct timespec { time_t tv_sec; long tv_nsec; }.
  • timespec_get(&ts, TIME_UTC) — preenche com o instante atual; devolve TIME_UTC em sucesso.
  • Cuidado com a formatação: use %09ld para zerar os nanossegundos à esquerda.
  • Subtração de dois timespec: a lógica do "empréstimo" dos nanossegundos evita durações negativas.
Código — t3m0906
#include <stdio.h>
#include <time.h>

int main(void) {
    struct timespec ts;

    if (timespec_get(&ts, TIME_UTC) != TIME_UTC) {
        printf("falha ao obter o tempo\n");
        return 1;
    }

    printf("segundos: %lld\n", (long long)ts.tv_sec);
    printf("nanossegundos: %ld\n", ts.tv_nsec);
    printf("combinado: %lld.%09ld\n", (long long)ts.tv_sec, ts.tv_nsec);

    return 0;
}
Saída esperada
> .	imespec-get.exe
> segundos: 1789503469
> nanossegundos: 243354400
> combinado: 1789503469.243354400
> 
> (Os valores exatos variam a cada execução; o formato é sempre <code>segundos.nanossegundos</code>.)

Exercício 3.09.2

Reescreva o programa de soma longa (seção 3) mas meça com time() (parede) e com clock() (CPU) ao mesmo tempo. Imprima soma, tempo de parede em s e tempo de CPU em s. Use um loop de 300000000 iteracoes.

Dica: Capture o início dos dois relogios antes do loop e o fim depois; a soma precisa ser impressa para o loop nao ser otimizado.

Ver solução
#include <stdio.h>
#include <time.h>

int main(void) {
    time_t t0 = time(NULL);
    clock_t c0 = clock();

    long long soma = 0;
    for (long long i = 0; i < 300000000LL; i++) {
        soma += i;
    }

    time_t t1 = time(NULL);
    clock_t c1 = clock();

    printf("soma: %lld\n", soma);
    printf("parede: %.0f s\n", difftime(t1, t0));
    printf("cpu: %.3f s\n", (double)(c1 - c0) / CLOCKS_PER_SEC);

    return 0;
}

Nível Intermediário

Exercício 3.09.3

Calcule a idade aproximada de uma pessoa: dado o nascimento (1990-07-20), imprima a idade em anos (a partir da data atual) e a idade em dias (usando mktime para fixar o nascimento e difftime na data atual).

Dica: Monte o nascimento num struct tm e use mktime; para os dias, divida a diferenca em segundos por 86400.

Ver solução
#include <stdio.h>
#include <time.h>

int main(void) {
    struct tm nat = {0};
    nat.tm_year = 1990 - 1900;
    nat.tm_mon = 6;
    nat.tm_mday = 20;

    time_t nasc = mktime(&nat);
    time_t agora = time(NULL);

    struct tm *atual = localtime(&agora);
    int anos = atual->tm_year - nat.tm_year;
    if (atual->tm_mon < nat.tm_mon ||
        (atual->tm_mon == nat.tm_mon && atual->tm_mday < nat.tm_mday)) {
        anos--;
    }

    long long dias = (long long)difftime(agora, nasc) / 86400LL;

    printf("nascimento: %04d-%02d-%02d\n",
           nat.tm_year + 1900, nat.tm_mon + 1, nat.tm_mday);
    printf("idade por ano: %d anos\n", anos);
    printf("idade por dias: %lld dias\n", dias);

    return 0;
}

Nível Avançado

Exercício 3.09.4

Complete o mini-log: um programa que abre "log.txt" em modo append, escreve uma linha no formato "[AAAA-MM-DDTHH:MM:SSzz] evento" (o T separando e o fuso com sinal), e imprime a mesma linha na tela. Execute duas vezes e confirme que o arquivo ganhou duas linhas.

Dica: Use strftime com uma mascara que termine em "%z" (fuso, ex. -0300). Abra com fopen("log.txt", "a").

Ver solução
#include <stdio.h>
#include <time.h>

int main(void) {
    time_t agora = time(NULL);
    struct tm *local = localtime(&agora);

    char linha[128];
    strftime(linha, sizeof linha, "%Y-%m-%dT%H:%M:%S%z", local);

    FILE *f = fopen("log.txt", "a");
    if (!f) {
        printf("nao foi possivel abrir log.txt\n");
        return 1;
    }
    fprintf(f, ">>> %s no evento: inicializacao concluida\n", linha);
    fclose(f);

    printf(">>> %s no evento: inicializacao concluida\n", linha);
    return 0;
}

Nível Avançado

Exercício 3.09.5

Compare fib(40) recursivo e iterativo: meça o tempo de CPU de cada implementacao com clock() e imprima os dois resultados e os dois tempos. O iterativo deve ser drasticamente mais rapido.

Dica: A versao recursiva ingênua chama a si mesma duas vezes por chamada; a iterativa mantem os dois ultimos valores com um loop.

Ver solução
#include <stdio.h>
#include <time.h>

long long fib_rec(int n) {
    if (n < 2) return (long long)n;
    return fib_rec(n - 1) + fib_rec(n - 2);
}

long long fib_ite(int n) {
    long long a = 0, b = 1;
    for (int i = 0; i < n; i++) {
        long long t = a;
        a = b;
        b = t + b;
    }
    return a;
}

int main(void) {
    clock_t c0 = clock();
    long long r1 = fib_rec(40);
    clock_t c1 = clock();
    long long r2 = fib_ite(40);
    clock_t c2 = clock();

    printf("fib(40) recursivo = %lld em %.3f s\n",
           r1, (double)(c1 - c0) / CLOCKS_PER_SEC);
    printf("fib(40) iterativo = %lld em %.3f s\n",
           r2, (double)(c2 - c1) / CLOCKS_PER_SEC);

    return 0;
}

🏗️ Miniprojeto: Registrador de log com carimbo de hora

Construa um pequeno registrador de eventos no estilo Quality System: o programa recebe mensagens pela entrada padrão (uma por linha) e as grava, em ordem, num arquivo "eventos.log", cada linha no formato ISO-8601 com fuso: "2026-09-15T17:20:31-0300 INFO sua mensagem aqui". No final, imprima quantas linhas foram gravadas e o tempo total de CPU gasto (clock()/CLOCKS_PER_SEC). Estrutura sugerida: funcao registrar(nivel, mensagem) que monta o carimbo com strftime, abre o arquivo em modo "a" a cada chamada e fecha na sequencia; o programa principal le linhas com fgets ate EOF.

Critérios de aceite

  • Carimbo usa strftime com %z e data corrente.
  • Mensagens chegam pela stdin (fgets), cada uma vira uma linha com rótulo INFO (ou o nível recebido).
  • Arquivo persistente entre execuções (modo "a").
  • Total de linhas impresso com printf ao final.
  • Tempo de CPU impresso em segundos com 3 casas.
