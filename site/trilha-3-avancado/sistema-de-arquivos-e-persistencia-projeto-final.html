Sistema de arquivos e persistência (projeto final)

Do fread/fwrite à serialização robusta: construa um gestor de inventário com arquivo binário e testes — o capstone da trilha.

Nível: Avançado Duração: ~35 min Pré-requisitos: Concluir os módulos 3.09–3.11 (tempo, inteiros exatos e ambiente) e saber arquivos (T2.13) e escopo/multiarquivos (T2.15).

🎯 Objetivos

Integrar tudo: structs com dados mistos, entrada robusta, arquivos binários e texto, separação de responsabilidades e testes práticos — entregando um Gestor de Inventário por linha de comando com persistência em arquivo binário e suíte de verificação.

Esqueleto do projeto: dados, menu e persistência

O projeto final é um Gestor de Inventário: um programa de linha de comando que mantém uma lista de itens (código, nome, quantidade, preço) num arquivo binário, com operações de adicionar, listar, buscar, alterar, remover e sair.

A arquitetura segue o padrão do King cap. 19: um cabeçalho (struct + protótipos), um arquivo de implementação (funções) e o main que só lê comandos. Dividir é o que torna o projeto testável e crescente.

Antes de escrever 400 linhas, desenhe o esqueleto: menu no main, um registro_exibe() para imprimir um item num formato único (a base de tudo) e as decisões binárias (um Registro de tamanho fixo, gravado com fwrite).

  • Separar em arquivos: inventario.h, inventario.c, main.c.
  • Registro fixo: struct Registro { int codigo; char nome[32]; int qtd; double preco; };.
  • Núcleo da exibição: void registro_exibe(const struct Registro *r) num formato único.
  • Num arquivo binário, cada registro tem sizeof(struct Registro) bytes.
Código — t3m1201
#include <stdio.h>

struct Registro {
    int codigo;
    char nome[32];
    int qtd;
    double preco;
};

void registro_exibe(const struct Registro *r) {
    printf("%04d | %-32s | qtd %d | R$ %.2f\n",
           r->codigo, r->nome, r->qtd, r->preco);
}

int main(void) {
    struct Registro r = { 1, "caneta azul", 12, 1.75 };
    registro_exibe(&r);
    return 0;
}

Gravando e lendo binário: fwrite/fread com fseeko

Persistir é escrever os bytes do struct no arquivo e, para ler de volta no lugar certo, posicionar-se com fseek/fseek(ftell). O par fwrite/fread recebe tamanho e quantidade de elementos — aqui, sizeof(struct Registro) e 1.

O protocolo do arquivo: começa com um cabeçalho de 4 bytes (o campo contagem de um struct de arquivo), depois N registros contíguos. O índice de um item é sizeof(struct Registro) vezes a posição.

No exemplo, gravamos um registro, fechamos e reabrimos em modo "rb", posicionamos no byte 4 do arquivo e lemos de volta — conferindo campo a campo que o "round-trip" preservou os dados. Esse é o teste mínimo de qualquer serialização.

  • fwrite(reg, sizeof *reg, 1, f) — grava o struct inteiro de uma vez.
  • fseek(f, offset, SEEK_SET) + fread(...) — lê o registro k a partir do offset k*sizeof.
  • Header do arquivo em um struct separado: struct Arquivo { int contagem; };.
  • Sempre confira os retornos de fwrite/fread (contagem de itens escrita/lida).
Código — t3m1202
#include <stdio.h>
#include <string.h>

struct Registro {
    int codigo;
    char nome[32];
    int qtd;
    double preco;
};

int main(void) {
    FILE *f = fopen("item.bin", "wb");
    if (!f) return 1;

    struct Registro r = { 7, "borracha", 25, 0.90 };
    printf("gravando %zu bytes\n", sizeof r);
    fwrite(&r, sizeof r, 1, f);
    fclose(f);

    f = fopen("item.bin", "rb");
    if (!f) return 1;

    struct Registro lido;
    fseek(f, 0, SEEK_SET);
    fread(&lido, sizeof lido, 1, f);
    fclose(f);

    if (lido.codigo == r.codigo && strcmp(lido.nome, r.nome) == 0 &&
        lido.qtd == r.qtd && lido.preco == r.preco) {
        printf("round-trip ok: %04d %s qtd=%d preco=%.2f\n",
               lido.codigo, lido.nome, lido.qtd, lido.preco);
    } else {
        printf("ERRO: dados divergem apos o round-trip\n");
    }

    return 0;
}

Teste como disciplina: um main de verificação

Antes de fechar o projeto, transforme as funções em um pequeno main de teste: um programa que liga as funções do inventário, verifica resultados esperados e contabiliza PASS/FAIL. Testar não é opcional num módulo de persistência — é como você prova que o formato binário não "vazou" um byte.

O padrão: cada teste chama uma função, compara o resultado com o esperado e imprime PASS ou FAIL; no final, imprime o resumo e devolve o número de falhas como código de saída (0 = todos passaram).

Assim, o seu gestor de inventário pode ser rodado tanto por um humano (menu) quanto por uma máquina (testes) — e é exatamente isso que scripts de Quality System esperam de um binário.

  • Função helper check(int ok, const char *nome) imprime PASS/FAIL.
  • Contadores: int passou, falhou; — resumo no final.
  • Código de saída = número de falhas (0 = sucesso).
  • Teste 4 coisas: inserir, listar (conta registros), buscar existente, buscar inexistente.
Código — t3m1203
#include <stdio.h>

static int passou = 0, falhou = 0;

static void check(int ok, const char *nome) {
    printf("%s %s\n", ok ? "PASS" : "FAIL", nome);
    if (ok) passou++; else falhou++;
}

static int soma_3(int a, int b, int c) {
    return a + b + c;
}

int main(void) {
    check(soma_3(1, 2, 3) == 6, "soma 1+2+3 = 6");
    check(soma_3(-1, 7, 0) == 6, "soma -1+7+0 = 6");
    check(soma_3(0, 0, 0) == 0, "soma 0+0+0 = 0");
    check(soma_3(100, 200, 300) == 600, "soma 100+200+300");

    printf("%d testes, %d falhas\n", passou + falhou, falhou);
    return falhou;
}

> PASS soma -1+7+0 = 6
> PASS soma 0+0+0 = 0
> PASS soma 100+200+300
> 4 testes, 0 falhas

Boas práticas e leitura reversa do registro

Um detalhe sutil do binário: gravar um struct inteiro com fwrite é rápido, mas o arquivo fica dependente do layout da struct (padrão de preenchimento/alinho do compilador). Para aprender a "costura fina", o projeto do módulo usa um formato texto (como alternativa) e o binário com struct — e você é convidado a experimentar os dois.

Profissionalmente, o formato de registro fixo em binário é o mais simples e ainda flexível. As regras de ouro: (1) abra sempre conferindo if (!f); (2) mantenha uma função abre_arquivo() única; (3) depois de cada operação que mexe no ponteiro do arquivo, feche e reabra para "resetar" a posição — isso evita bugs de fseek mal lembrado.

E lembre-se: fluxo de dados errado é invisível. A disciplina de registro_exibe() faz com que qualquer lista impressa seja idêntica, em qualquer função — comparável em um teste automático.

  • Abra arquivos sempre validando o retorno; dê mensagem em stderr.
  • Uma única função abre() central os modos de abertura usados.
  • Feche depois de operações e reabra para evitar fseek esquecido.
  • Compare sempre via registro_exibe para verificação visual e textual invariante.

Exercício 3.12.1

Crie a funcao int registro_busca(FILE *f, int codigo, struct Registro *saida) que percorre os registros do arquivo (do offset 4 em diante, apos o cabeçalho de contagem) e preenche *saida se encontrar o codigo; devolve 1 se achou, 0 se nao. Teste com dois items gravados (codigos 10 e 40) procurando 40 e depois 999.

Dica: O arquivo com N registros tem 4 + N*sizeof(struct Registro) bytes. fread em loop ate EOF ou ate o fim calculado.

Ver solução
#include <stdio.h>
#include <string.h>

struct Registro {
    int codigo;
    char nome[32];
    int qtd;
    double preco;
};

int registro_busca(FILE *f, int codigo, struct Registro *saida) {
    fseek(f, 4, SEEK_SET);
    struct Registro r;
    while (fread(&r, sizeof r, 1, f) == 1) {
        if (r.codigo == codigo) {
            *saida = r;
            return 1;
        }
    }
    return 0;
}

int main(void) {
    FILE *f = fopen("buf.bin", "wb");
    if (!f) return 1;
    struct Registro items[2];
    items[0].codigo = 10; strcpy(items[0].nome, "item dez"); items[0].qtd = 1; items[0].preco = 1.0;
    items[1].codigo = 40; strcpy(items[1].nome, "item quarenta"); items[1].qtd = 2; items[1].preco = 2.5;
    int cont = 2;
    fwrite(&cont, sizeof cont, 1, f);
    fwrite(items, sizeof(struct Registro), cont, f);
    fclose(f);

    f = fopen("buf.bin", "rb");
    if (!f) return 1;

    struct Registro achado;
    if (registro_busca(f, 40, &achado)) {
        printf("codigo %d encontrado: %s\n", achado.codigo, achado.nome);
    } else {
        printf("codigo %d nao encontrado\n", 40);
    }

    if (registro_busca(f, 999, &achado)) {
        printf("codigo 999 encontrado: %s\n", achado.nome);
    } else {
        printf("codigo 999 nao encontrado\n");
    }

    fclose(f);
    return 0;
}

./ex12_1 — o fseek(f, 4, SEEK_SET) pula o cabeçalho de contagem (4 bytes) antes da busca; sem ele, o contador seria lido como um registro falso.

Exercício 3.12.2

Escreva o esqueleto completo do gestor com as funcoes salva(cont, items, nome_arquivo) e carrega(cont, items, nome_arquivo) que gravam/leem, respetivamente, o cabeçalho e os registros. No main, crie 3 registros, salve, leia de volta e imprima via registro_exibe, conferindo no final quantos foram lidos.

Dica: O struct Arquivo { int contagem; } evita ler bool falso; acesse items[c] apos carregar com base em cont.

Ver solução
#include <stdio.h>
#include <string.h>

struct Registro {
    int codigo;
    char nome[32];
    int qtd;
    double preco;
};

struct Arquivo {
    int contagem;
};

void registro_exibe(const struct Registro *r) {
    printf("%04d | %-32s | qtd %d | R$ %.2f\n",
           r->codigo, r->nome, r->qtd, r->preco);
}

void salva(int cont, const struct Registro *items, const char *nome) {
    FILE *f = fopen(nome, "wb");
    if (!f) return;
    struct Arquivo h = { cont };
    fwrite(&h, sizeof h, 1, f);
    fwrite(items, sizeof(struct Registro), cont, f);
    fclose(f);
}

int carrega(struct Registro *items, const char *nome) {
    FILE *f = fopen(nome, "rb");
    if (!f) return 0;
    struct Arquivo h;
    if (fread(&h, sizeof h, 1, f) != 1) { fclose(f); return 0; }
    int n = fread(items, sizeof(struct Registro), h.contagem, f);
    fclose(f);
    return n;
}

int main(void) {
    struct Registro items[8];
    items[0].codigo = 1;  strcpy(items[0].nome, "caneta");    items[0].qtd = 12; items[0].preco = 1.75;
    items[1].codigo = 2;  strcpy(items[1].nome, "lapis");     items[1].qtd = 8;  items[1].preco = 0.80;
    items[2].codigo = 3;  strcpy(items[2].nome, "regua");     items[2].qtd = 4;  items[2].preco = 3.20;

    salva(3, items, "inventario.bin");

    struct Registro lidos[8];
    int n = carrega(lidos, "inventario.bin");
    printf("gravados 3 registros; lidos %d:\n", n);
    for (int i = 0; i < n; i++) {
        registro_exibe(&lidos[i]);
    }

    return 0;
}

🏗️ Miniprojeto: Gestor de inventário CLI com persistência binária

Construa o projeto final completo da trilha: um Gestor de Inventário com menu de texto e persistência em arquivo binário. Comandos: (1) adicionar item, (2) listar, (3) buscar por código, (4) alterar quantidade, (5) remover, (0) sair. Um arquivo "inventario.bin" guarda o cabeçalho (int contagem) seguido de N registros (struct: codigo int, nome char[32], qtd int, preco double). O menu é um loop com a leitura segura de fgets+strtol; toda alteração reescreve o arquivo do zero (padrão simples e robusto). Testes: um arquivo main de teste ativa as funções (busca existe/não existe, salvar+carregar round-trip) e imprime PASS/FAIL com resumo.

Critérios de aceite

  • Menu funcional com os 6 comandos e validação de entrada (não trava com texto).
  • Persistência: salvar/carregar com cabeçalho+registros; round-trip sem perda de campos.
  • registro_exibe única para tudo.
  • Busca devolve 0/1 e preenche saida.
  • Remoção compacta (reordena, decrementa contagem).
  • main de teste com PASS/FAIL e resumo, saída 0 se 0 falhas.
  • Código organizado em arquivos (inventario.h/inventario.c/main.c) na entrega.
  • Compila com gcc -Wall -Wextra -std=c11 sem avisos.
