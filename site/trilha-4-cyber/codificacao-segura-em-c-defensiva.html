4.02

Codificação segura em C (defensiva)

Funções perigosas, bounds checking e compilação defensiva

Nível: Intermediário/Cyber Duração: ~1h Pré-requisitos: T0.01 (gcc), T2.05 (strings e ponteiros)

🎯 Objetivos

Aprender a escrever C à prova de entrada hostil: substituir gets/strcpy/strcat/sprintf e scanf("%s") por variantes com limite, implementar bounds checking explícito, conhecer TOCTOU, e blindar a build com flags (-fstack-protector, -D_FORTIFY_SOURCE, -Wformat-security) e sanitizers (ASan/UBSan) e valgrind.

📖 Leitura guiada

Foco da leitura: Consulte a página da OWASP sobre Buffer Overflow (https://owasp.org/www-community/vulnerabilities/Buffer_Overflow) e as entradas CWE-120 (buffer copy sem checagem), CWE-121 (stack-based overflow) e CWE-119 (falha de limites de memória) em https://cwe.mitre.org/ — as CWEs são o vocabulário que usamos para classificar bugs nesta trilha.

A regra de ouro da entrada de dados

A regra de ouro da codificação segura em C é curta: nenhuma operação de memória pode assumir que a entrada cabe no alvo. Sempre que copiar, concatenar ou formatar dados vindos de fora, o programador deve dizer quantos bytes o destino aguenta. Este módulo ensina as três trocas que resolvem 80% dos problemas triviais:

  • gets → fgets (com tamanho máximo).
  • strcpy/strcat/sprintf → versões com limite de destino (snprintf, strncpy com cuidado no NUL, ou cópia manual com tamanho).
  • scanf("%s", …) → fgets que lê a linha inteira de uma vez.

Caso 1: gets (removida do padrão C11)

gets lê do teclado sem nenhum limite e foi removida do padrão C11 (por isso muitos compiladores emitem um aviso forte). Qualquer linha mais longa que o buffer estoura a pilha. Este exemplo é didático: compile-o no Linux/WSL apenas para ver o aviso do gcc e o comportamento estourado.

Código — gets_demo.c (VULNERÁVEL)
/* gets_demo.c -- compila com WARNING no Linux.
   gcc -Wall -Wextra -std=c11 gets_demo.c -o gets_demo   (Linux/WSL) */
#include <stdio.h>

int main(void)
{
    char nome[8];
    printf("Seu nome: ");
    gets(nome);          /* sem limite: estoura nome */
    printf("Ola, %s!\n", nome);
    return 0;
}
Saída esperada
$ gcc -Wall -Wextra -std=c11 gets_demo.c -o gets_demo
gets_demo.c: In function 'main':
warning: implicit declaration of function 'gets' ...
warning: cast between incompatible function types ...
$ ./gets_demo
Seu nome: miguel
Ola, miguel!

A versão corrigida com fgets

fgets(ptr, tamanho, stdin) lê no máximo tamanho-1 caracteres e sempre grava o \0 no final — é a substituição direta do gets. tamanho aqui é o tamanho total do buffer (8 no nosso caso), não "8-1"; o fgets nunca ultrapassa o alvo.

Código — gets_fixed.c (SEGURO)
/* gets_fixed.c -- versao segura com fgets.
   gcc -Wall -Wextra -std=c11 gets_fixed.c -o gets_fixed   (compila em qualquer SO) */
#include <stdio.h>

int main(void)
{
    char nome[8];
    printf("Seu nome: ");
    if (fgets(nome, sizeof nome, stdin) == NULL) {
        return 1;
    }
    printf("Ola, %s", nome);
    return 0;
}
Saída esperada
$ ./gets_fixed
Seu nome: miguel
Ola, miguel

Caso 2: strcpy/strcat/sprintf e a família com limite

As três cópias clássicas não recebem o tamanho do destino:

  • strcpy(dest, src) — copia até o \0 de src; estoura se src for maior que dest.
  • strcat(dest, src) — igual, mas anexa após o \0 atual de dest; o destino precisa de espaço para o que já tem + o que entra.
  • sprintf(dest, fmt, …) — formata produzindo uma string; o destino precisa conter o texto formatado.
Código — copia_perigosa.c (VULNERÁVEL)
/* copia_perigosa.c -- demonstra estouro silencioso (VULNERAVEL).
   gcc -Wall -Wextra -std=c11 copia_perigosa.c -o copia_perigosa
   Rode no Linux/WSL com ASAN se quiser ver o estouro gritar:
   gcc -fsanitize=address copia_perigosa.c -o copia_perigosa_asan
   (o pacote libasan precisa estar instalado: sudo apt install gcc) */
#include <stdio.h>
#include <string.h>

int main(void)
{
    char destino[10];
    char atacante[64];

    memcpy(atacante, "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ", 37);
    atacante[37] = '\0';

    /* destino[10] NAO consegue segurar 37 bytes: estoura a pilha */
    strcpy(destino, atacante);

    printf("destino = %s\n", destino);
    return 0;
}
Saída esperada
$ gcc -Wall -Wextra -std=c11 copia_perigosa.c -o copia_perigosa
copia_perigosa.c: In function 'main':
warning: 'strcpy' writing 37 bytes into a region of size 10 ...
$ ./copia_perigosa_asan
==12345==ERROR: AddressSanitizer: stack-buffer-overflow ...

A versão corrigida com limite explícito

A substituição direta é strncpy(dest, src, n) — mas atenção: strncpy não garante o \0 final se src tiver >= n bytes; por isso o padrão defensivo é strncpy(dest, src, n-1); dest[n-1] = 0;. Para formatação, use snprintf(dest, n, fmt, …), que grava \0 sempre.

Código — copia_segura.c (SEGURO)
/* copia_segura.c -- com limpeza e padrao defensivo.
   gcc -Wall -Wextra -std=c11 copia_segura.c -o copia_segura  (qualquer SO) */
#include <stdio.h>
#include <string.h>

#define BUFSZ 32

static void copiar_segura(char *dest, size_t n, const char *src)
{
    if (n == 0) return;
    strncpy(dest, src, n - 1);   /* copia no maximo n-1 */
    dest[n - 1] = '\0';          /* garante terminacao */
}

int main(void)
{
    char destino[BUFSZ];
    char entrada[256];
    char atacante[64];

    memcpy(atacante, "0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ", 37);
    atacante[37] = '\0';

    copiar_segura(destino, sizeof destino, atacante);
    puts("Copiado com limite:");
    puts(destino);
    return 0;
}
Saída esperada
$ ./copia_segura
Copiado com limite:
0123456789ABCDEFGHIJ

Caso 3: scanf("%s") e a versão com fgets

scanf("%s", buf) não tem limite e ainda quebra em espaços. A alternativa robusta: ler a linha inteira com fgets e fazer parsing depois com sscanf/manipulação manual (com o buffer já limitado).

Código — scanf_vs_fgets.c
/* scanf_vs_fgets.c -- maneiras de ler uma palavra com limite.
   gcc -Wall -Wextra -std=c11 scanf_vs_fgets.c -o scanf_vs_fgets */
#include <stdio.h>
#include <string.h>

int main(void)
{
    char palavra[16];

    /* MAU: sem limite, estoura se a palavra passar de 15 chars */
    /* scanf("%s", palavra); */

    /* BOM: fgets limita, mas guarda o \n no final */
    printf("Digite uma palavra: ");
    if (fgets(palavra, sizeof palavra, stdin) == NULL) return 1;
    palavra[strcspn(palavra, "\n")] = '\0';   /* remove o \n final */

    printf("Voce digitou: %s\n", palavra);
    return 0;
}
Saída esperada
$ ./scanf_vs_fgets
Digite uma palavra: senha123
Voce digitou: senha123

Bounds checking: o contrato é o tamanho do alvo

Bounds checking = o código pergunta ao destinatário quantos bytes ele aguenta antes de qualquer cópia. Quando você escreve funções que recebem buffers (cópia, concatenação, formatação), exija o tamanho como parâmetro e valide na entrada:

Código — bounds.c (funcao com tamanho)
/* bounds.c -- una funcao segura recebe (destino, tamanho, fonte).
   gcc -Wall -Wextra -std=c11 bounds.c -o bounds  (qualquer SO) */
#include <stdio.h>
#include <string.h>

static size_t concat_seguro(char *dest, size_t n, const char *src)
{
    size_t ja = strnlen(dest, n);      /* quanto ja ha no destino */
    if (ja >= n) return n;             /* destino cheio */
    size_t cabem = n - ja - 1;         /* espaco livre (menos o NUL) */
    strncpy(dest + ja, src, cabem);
    dest[n - 1] = '\0';
    return strnlen(dest, n);
}

int main(void)
{
    char log[32] = "inicio: ";
    concat_seguro(log, sizeof log, "usuario=miguel, acao=login, ok");
    puts(log);
    return 0;
}
Saída esperada
$ ./bounds
inicio: usuario=miguel, acao=log

TOCTOU (menção)

TOCTOU (Time-Of-Check To Time-Of-Use) é a classe de bug em que o programa verifica uma condição (ex.: access(caminho, W_OK)), e entre a verificação e o uso o estado muda (ex.: um atacante troca o arquivo por um symlink). Em C, envolve chamadas de sistema atômicas (open com flags corretas) em vez de checar e depois abrir. Lembre-se apenas do nome e do padrão por enquanto — você vai reconhecê-lo na vida real quando vir "chequei, depois usei, sem atomicidade".

Compilação defensiva: flags que ajudam

O gcc tem proteções que o programador liga uma vez, na build. Custo do desenvolvimento no estudo: zero. Em produção: mitigações reais.

  • -fstack-protector-all — injeta canários de pilha (valor aleatório perto do return address); se o overflow destruir o canário, o programa aborta automaticamente.
  • -D_FORTIFY_SOURCE=2 — enriquece funções conhecidas (strcpy, sprintf, memcpy) com checagens de tamanho EM TEMPO DE EXECUÇÃO quando o compilador conhece o tamanho do alvo; precisa ser combinado com -O1 ou superior.
  • -Wformat -Wformat-security -Werror=format-security — transforma em erro o uso de format string com entrada do usuário (o bug do módulo 07).
  • -fno-stack-protector — é a flag de desativação; NÃO a use em código real. Só nos módulos de exploração didática (05-07).
Código — flags defensivas
# build defensiva recomendada para o codigo REAL (Linux e/ou MinGW):
gcc -O2 -Wall -Wextra -Wformat -Wformat-security -Werror=format-security     -fstack-protector-all -D_FORTIFY_SOURCE=2 -o app app.c

Sanitizers (runtime) e valgrind

A compilação defensiva evita, mas o sanitizer flagra. O ASan (Address Sanitizer) reescreve seu programa para detectar overflow/use-after-free em tempo de execução; o UBSan faz o mesmo para comportamento indefinido (unsigned wrap está fora, mas nan/invalid, overflow signed etc. entram). Valgrind simula a CPU e caça vazamentos e acessos inválidos sem recompilar.

  • ASan: gcc -fsanitize=address -g demo.c -o demo. Precisa do libasan — no Ubuntu, instalado junto com o gcc; no MinGW do Windows não está disponível. Use WSL. Ao rodar, a primeira escrita fora do buffer para o programa com um relatório detalhado.
  • UBSan: gcc -fsanitize=undefined -g demo.c -o demo. Acusa divisão por zero, estouro de int com sinal, etc.
  • Valgrind: valgrind --leak-check=full ./demo. Roda o binário normal sem recompilar; reporta leaks e invalid read/write. Mais lento que ASan, mas não exige flags novas.
  • No CI (integração contínua) de um projeto real, compile SEMPRE com um sanitizer em uma das jobs — é o teste de regressão de memória mais barato que existe.
Código — asan ubasan e valgrind
# observando um overflow com ASan (Linux/WSL; precisa do libasan)
gcc -Wall -g -fsanitize=address copia_perigosa.c -o copia_perigosa_asan
./copia_perigosa_asan
Saída esperada
==14725==ERROR: AddressSanitizer: stack-buffer-overflow on address 0x7fff...
    #0 0x... in main copia_perigosa.c:11
  ...
  The signal is caused by a WRITE memory access.
  SUMMARY: AddressSanitizer: stack-buffer-overflow ...

Como se defender

  • Nunca use gets, strcpy, strcat, sprintf ou scanf("%s", …) sem limite — use fgets e snprintf, ou suas próprias funções com tamanho do destino.
  • Todo buffer recebe tamanho de alvo nas funções que você escrever; um char *buf sem size_t n ao lado é um bilhete de estouro.
  • Trate toda entrada como hostil: tamanho baseado em sizeof/parâmetro, nunca em um comprimento declarado pelo remetente.
  • Compile com o combo defensivo (-fstack-protector-all -D_FORTIFY_SOURCE=2 -Wformat-security -Werror=format-security).
  • Rode ASan (WSL) ou valgrind em testes; ambos transformam "estourou silenciosamente" em "parou com endereço e pilha de chamadas".
  • Lide com o return value das chamadas de I/O (NULL do fgets) — entrada truncada ainda é entrada válida.
  • Empacote as regras no seu time: code review tem checklist mínimo (procure gets/strcpy/sprintf na busca de texto do repositório).

✏️ Exercícios

Nível 1

Exercício 4.02.1

Escreva login.c que pergunta uma senha com fgets num buffer de 16 bytes e imprime quantos caracteres foram digitados (com strlen) e se a senha está totalmente contida no buffer hint: compare strlen com o espaço disponível. Depois teste digitando uma linha de 40 caracteres: o programa NÃO deve estourar e deve imprimir o tamanho truncado.

Dica: Use fgets(pass, sizeof pass, stdin); depois remova o \n com pass[strcspn(pass, "\n")] = 0.

Ver solução
#include <stdio.h>
#include <string.h>

int main(void)
{
    char pass[16];
    printf("Senha: ");
    if (fgets(pass, sizeof pass, stdin) == NULL) return 1;
    pass[strcspn(pass, "\n")] = '\0';
    printf("Recebi %zu caracteres\n", strlen(pass));
    if (strlen(pass) >= sizeof pass) {
        printf("Atencao: entrada truncada\n");
    }
    return 0;
}

Com 40 caracteres, fgets guarda apenas os primeiros 15 + NUL; strlen retorna 15 e o aviso dispara.

Nível 2

Exercício 4.02.2

Crie concat.c com uma função concat_seguro (como na seção de bounds) e monte a mensagem "erro na linha 7" a partir de duas strings, garantindo que nunca estoure um buffer de 20 bytes. Mostre com uma entrada longa que o resultado é truncado, não corrompido.

Dica: Use snprintf(dest, n, "%s%s", a, b) — mais simples e sempre termina com NUL.

Ver solução
#include <stdio.h>

int main(void)
{
    char msg[20];
    const char *pre = "erro na linha ";
    snprintf(msg, sizeof msg, "%s%s", pre, "7");
    puts(msg);

    /* entrada hostil longa: truncada, nunca estoura */
    snprintf(msg, sizeof msg, "%s%s",
             pre, "123456789012345678901234567890");
    puts(msg);
    return 0;
}

Note que snprintf retorna o tamanho que seria escrito — útil para detectar truncamento (float no buffer).

Nível 2

Exercício 4.02.3

Compile copia_perigosa.c com -fsanitize=address no WSL e rode. Leia o relatório do ASan: identifique a linha do estouro e o endereço. Depois recompile a versão segura e confirme que o ASan fica quieto.

Dica: Procure no relatório o texto "stack-buffer-overflow" e a linha com copia_perigosa.c:N.

Ver solução
$ gcc -Wall -g -fsanitize=address copia_perigosa.c -o copia_perigosa_asan
$ ./copia_perigosa_asan

❓ Verificação rápida

🏗️ Miniprojeto: Mini-biblioteca strsafe

Escreva strsafe.h/.c com três funções defensivas: (1) strs_copiar(dest, n, src), (2) strs_anexar(dest, n, src) e (3) strs_escrever(dest, n, fmt, …) (wrapper de vsnprintf). Todas garantem NUL final e retornam -1 em truncamento (com errno = ENAMETOOLONG se quiser sofisticar). Depois escreva um teste main que tenta estourar cada função com entradas de 10x o tamanho do buffer e comprove: nada estoura, tudo termina em 0. Compile o projeto com as flags defensivas da seção.

Critérios de aceite

  • As três funções aceitam (destino, tamanho, fonte/args) — o tamanho do alvo é sempre explícito.
  • Nenhuma função usa gets/strcpy/strcat/sprintf sem limite.
  • Compila com o combo defensivo sem warnings: gcc -Wall -Wextra -Wformat-security -Werror=format-security -fstack-protector-all.
  • O teste com entradas gigantes não gera nenhum estouro (ASan silencioso no WSL ou valgrind limpo).
  • Cada função retorna uma indicação (0 ok / -1 truncou).
