2.09

Programas multiarquivo e compilação separada

.h, .c, protótipos, guardas, static/extern, Makefile

Nível: Intermediário Duração: ~45 min Pré-requisitos: T2.08

🎯 Objetivos

Dividir um programa em cabeçalhos (.h) e implementações (.c), compilar peça por peça com gcc -c, linkar tudo depois, e automatizar a build com um Makefile simples com build incremental.

📖 Leitura guiada

Beej's Guide: Capítulo 17 (Separate Compilation, Makefiles)

King (livro em PDF): Capítulo 15 (Writing Large Programs)

Foco da leitura: No King, o capítulo 15 cobre exatamente o cenário aqui: dividir em arquivos, cabeçalhos, e o papel das guardas. No Beej, foque na parte de compilar vários arquivos e no exemplo de Makefile.

O cabeçalho: só declarações

A regra do jogo: o .h traz apenas declarações (protótipos, tipos, macros, constantes); o .c traz as definições concretas. Quem quer usar uma função faz #include "calc.h" e o compilador sabe a assinatura. A include guard evita duplicação (T2.08).

Este bloco é um cabeçalho; os dois próximos são as peças compiláveis que, juntas, formam o programa.

Código — calc.h (fragmento de cabeçalho)
/* calc.h */
#ifndef CALC_H
#define CALC_H

int soma(int a, int b);
int sub(int a, int b);
int mul(int a, int b);

#endif

A implementação: definitions

calc.c inclui o próprio cabeçalho — assim o compilador confere se o protótipo bate com a definição. Note que este arquivo não tem main: é uma biblioteca, um translação unit que só fará sentido ao ser linkado com quem tem main.

Código — calc.c
/* calc.c */
#include "calc.h"

int soma(int a, int b) { return a + b; }
int sub(int a, int b)  { return a - b; }
int mul(int a, int b)  { return a * b; }

O programa principal

main.c usa as funções com a interface declarada no calc.h. Para gerar o executável, gcc calc.c main.c -o calc: o compilador gera objetos de cada .c e o linker junta tudo, resolvendo as chamadas.

Código — main.c
/* main.c */
#include <stdio.h>
#include "calc.h"

int main(void)
{
    printf("soma: %d\n", soma(3, 4));
    printf("sub:  %d\n", sub(10, 4));
    printf("mul:  %d\n", mul(3, 4));
    return 0;
}
Saída esperada
> gcc calc.c main.c -o calc
> .\calc.exe

soma: 7
sub:  6
mul:  12

Compilação separada: gcc -c e os arquivos .o

Projetos grandes compilam cada .c em um arquivo objeto (.o) com gcc -c, e só a mudança de um arquivo exige recompilar aquele arquivo. No fim, o linker junta os .o no executável:

Código — compilando-por-partes
gcc -Wall -Wextra -std=c11 -c calc.c
gcc -Wall -Wextra -std=c11 -c main.c
gcc calc.o main.o -o calc
.\calc.exe
Saída esperada
soma: 7
sub:  6
mul:  12

Makefile: build incremental por dependências

Um Makefile descreve alvos (targets), pré-requisitos e regras: se qualquer pré-requisito mudou, o alvo é reconstruído. Isso dá o build incremental — imagina recompilar 200 arquivos porque trocou 1.

Abaixo, o Makefile do nosso mini-projeto (no Windows, use mingw32-make):

  • calc: — alvo final, depende de calc.o e main.o.
  • calc.o: e main.o: — dependem de seus .c e do calc.h.
  • clean: — remove os artefatos gerados.
Código — Makefile
# Makefile
CC = gcc
CFLAGS = -Wall -Wextra -std=c11

calc: calc.o main.o
	$(CC) $(CFLAGS) calc.o main.o -o calc

calc.o: calc.c calc.h
	$(CC) $(CFLAGS) -c calc.c

main.o: main.c calc.h
	$(CC) $(CFLAGS) -c main.c

clean:
	del /q calc.o main.o calc.exe

static e extern

extern diz que uma variável/função está definida em outro arquivo (já é o padrão para funções). static no nível de arquivo esconde o símbolo daquele arquivo (linkage interna); static dentro de função preserva o valor entre chamadas — a "memória" da função:

Código — contador-static.c
#include <stdio.h>

int chamadas_estaticas(void)
{
    static int contador = 0;
    contador++;
    return contador;
}

int main(void)
{
    printf("chamada 1: %d\n", chamadas_estaticas());
    printf("chamada 2: %d\n", chamadas_estaticas());
    printf("chamada 3: %d\n", chamadas_estaticas());
    return 0;
}
Saída esperada
chamada 1: 1
chamada 2: 2
chamada 3: 3

✏️ Exercícios

Nível 2

Exercício 2.09.1

Separe em media.h e media.c a função double media(double a, double b) e use-a em um main.c. Responda com os três arquivos e o comando de compilação. (Solução mostra uma versão compacta e a regra de ouro dos arquivos.)

Dica: media.h declara e media.c define. main.c inclui media.h e chamam media(7.5, 4.5).

Ver solução
/* media.h */
#ifndef MEDIA_H
#define MEDIA_H
double media(double a, double b);
#endif

/* media.c */
#include "media.h"
double media(double a, double b) { return (a + b) / 2.0; }

/* main.c */
#include <stdio.h>
#include "media.h"
int main(void)
{
    printf("media de 7.5 e 4.5 = %.2f\n", media(7.5, 4.5));
    return 0;
}

/* compilar: gcc media.c main.c -o media */

Na prática, cada arquivo vai em um arquivo de verdade (.h e .c); a solução acima junta os três em um código único só para conferência rápida.

Nível 2

Exercício 2.09.2

Com os arquivos do exemplo calc (calc.h/calc.c/main.c), compile manualmente em duas etapas: gere os objetos com gcc -c e linke com os .o. Depois, usando o Makefile, rode mingw32-make duas vezes seguidas e observe como a segunda build é mais curta (nothing to be done).

Dica: O Makefile deve estar na mesma pasta dos .c. A segunda execução imprime "make: Nothing to be done".

Ver solução
> gcc -Wall -Wextra -std=c11 -c calc.c main.c
> gcc calc.o main.o -o calc
> .\calc.exe
soma: 7
sub:  6
mul:  12

> mingw32-make
calc.o  (ou "nada a fazer" na segunda vez)
> .\calc.exe

O Makefile compara timestamps: nada que mudou, nada a recompilar.

Nível 3

Exercício 2.09.3

Escreva uma função com static int contador que devolve 1, 2, 3... a cada chamada (o exemplo do módulo). Agora alterne: crie uma versão SEM static (sempre 1) e outra COM static, em um só programa, e imprima as duas sequências lado a lado.

Dica: A função sem static reinicia em 0 a cada chamada; a com static lembra.

Ver solução
#include <stdio.h>

int sem_static(void)
{
    int c = 0;
    c++;
    return c;
}

int com_static(void)
{
    static int c = 0;
    c++;
    return c;
}

int main(void)
{
    for (int i = 0; i < 4; i++) {
        printf("sem_static:%d   com_static:%d\n", sem_static(), com_static());
    }
    return 0;
}

A variável static vive entre chamadas; a local morre ao fim da função.

Nível 4

Exercício 2.09.4

Use extern: em global.c defina int contador_global = 0; e a função void incrementar_global(void); em main.c declare extern int contador_global;, chame a função três vezes e imprima o valor. Compile com os dois arquivos.

Dica: precisa de dois arquivos; responda com o conteúdo de cada um e o comando gcc global.c main.c -o prog.

Ver solução
/* global.c */
int contador_global = 0;

void incrementar_global(void)
{
    contador_global++;
}

/* main.c */
#include <stdio.h>

extern int contador_global;
void incrementar_global(void);

int main(void)
{
    incrementar_global();
    incrementar_global();
    incrementar_global();
    printf("contador_global = %d\n", contador_global);
    return 0;
}

/* compilar: gcc global.c main.c -o prog  -> imprime 3 */

extern não é uma declaração "nova": apenas promete que a variável existe em outro arquivo. O linker resolve na fase de linkagem.
