Preparando o ambiente de desenvolvimento

gcc, editor, terminal e primeiros comandos

Nível: Iniciante Duração: ~45 min Pré-requisitos: Nenhum

🎯 Objetivos

Deixar seu computador pronto para escrever, compilar e executar programas em C com confiança: entender o que o gcc faz, compilar um programa, ver erros de compilação e dar os primeiros passos no depurador gdb.

Beej's Guide: Capítulo 2, seções 2.4–2.7 (Building with gcc, clang, IDEs)

As ferramentas que você já tem

Você já tem o compilador gcc instalado (MinGW-w64). Isso é o essencial. Para acompanhar o curso você precisa apenas de:

  • gcc (compilador) — já instalado. No terminal, confira com gcc --version.
  • Um editor de código — VS Code, Notepad++, Sublime ou o próprio Vim/Neovim. Qualquer um serve; o importante é salvar arquivos em texto puro.
  • PowerShell (que você já usa) ou o Windows Terminal padrão do Windows 11.
  • git (recomendado, para versionar seus exercícios) — instale de https://git-scm.com se ainda não tiver.

O que o gcc faz: do .c ao executável

Quando você roda gcc prog.c, o compilador executa quatro etapas em sequência:

  • Pré-processamento (cpp): resolve as diretivas #include, #define etc.; gera um arquivo gigante "achatado".
  • Compilação: transforma o C em assembly (linguagem da CPU).
  • Montagem (as): transforma assembly em código de máquina, dentro de um arquivo objeto (.o).
  • Linkagem (ld): junta seu código com a biblioteca padrão (stdio, string...) e produz o executável final.
Código — pipeline do compilador
# Etapas que o gcc executa por baixo dos panos:
gcc -E prog.c      > prog.i   # 1. pré-processamento
gcc -S prog.i               # 2. compilação  -> prog.s (assembly)
gcc -c prog.s               # 3. montagem    -> prog.o (objeto)
gcc prog.o -o prog          # 4. linkagem    -> prog (executável)

Seu primeiro programa compilado

Crie um arquivo chamado hello.c com o conteúdo abaixo. Preste atenção em cada linha: a diretiva #include <stdio.h> traz as declarações de printf; cada programa em C tem uma função main, que é o ponto de entrada; printf imprime; return 0; diz ao sistema operacional que o programa terminou com sucesso.

Código — hello.c
#include <stdio.h>

int main(void)
{
    printf("Olá, mundo!\n");
    return 0;
}
Saída esperada
> gcc -Wall -Wextra -std=c11 hello.c -o hello
> .\hello.exe

Olá, mundo!

Flags do gcc que você vai usar o tempo todo

As flags abaixo viram sua "higiene de compilação". Acostume-se a usá-las em todos os exercícios:

  • -Wall -Wextra — liga avisos valiosos (warnings). Código limpo compila sem nenhum aviso.
  • -std=c11 — fixa o padrão da linguagem (C11). Também existem c99 e c17.
  • -g — inclui informações de depuração (necessário para o gdb).
  • -O0 / -O2 — nível de otimização. -O0 (padrão) para estudar; -O2 para programar "de verdade".
  • -o nome — nome do executável de saída (senão o gcc gera a.exe).
Código — compilando com boas práticas
gcc -Wall -Wextra -std=c11 -g -O0 hello.c -o hello

Como ler um erro de compilação

Erros de compilação têm um formato padronizado: arquivo, linha, coluna, e a mensagem. Sempre corrija o primeiro erro primeiro — erros seguintes costumam ser "efeito colateral" dos anteriores.

Código — um erro de exemplo (falta o ;)
#include <stdio.h>

int main(void)
{
    printf("Olá\n")   // <-- falta o ponto e vírgula aqui
    return 0;
}
Saída esperada
hello.c:5:5: error: expected ';' before 'return'
    5 |     printf("Olá\n")
      |     ^
      |     ;
    6 |     return 0

Primeiros passos no depurador gdb

O gdb (GNU Debugger) deixa você executar o programa passo a passo e inspecionar variáveis — o que é essencial quando um programa compila mas não faz o que deveria. Na Trilha 4 (Cyber) vamos usar isso pesado. Por enquanto, aprenda os 4 comandos básicos:

  • gdb ./hello.exe — abre o depurador com o programa carregado.
  • break main — pausa a execução na função main.
  • run (ou r) — roda o programa até o breakpoint.
  • next (ou n) + print var — avança uma linha e imprime o valor de uma variável.
Código — sessão gdb
gdb ./hello.exe
(gdb) break main
(gdb) run
(gdb) next
(gdb) print "chegamos até aqui"
(gdb) quit

Organizando seus projetos

Crie uma pasta exercicios dentro desta (a pasta aprenda-c) e um subpasta por exercício. Sempre que terminar um exercício, compile com a dupla -Wall -Wextra e garanta zero avisos. A consistência de poucas pastas organizadas vale mais do que ferramentas sofisticadas nesta fase.

  • Pastas sugeridas: exercicios/, projetos/, labs/ (para a trilha Cyber).
  • Nomeie os arquivos com padrão: ex01.c, ex02.c, ...
  • Salve seus arquivos como UTF-8 (padrão dos editores modernos).

✏️ Exercícios

Nível 1

Exercício 0.01.1

Crie o arquivo eu.c que imprime seu nome e sua cidade em duas linhas. Compile com gcc -Wall -Wextra -std=c11 eu.c -o eu e rode. Se houver algum aviso, corrija até zerar.

Dica: Use dois printf ou um só com \n no meio.

Ver solução
#include <stdio.h>

int main(void)
{
    printf("Seu Nome Aqui\n");
    printf("Sua Cidade\n");
    return 0;
}
Nível 1

Exercício 0.01.2

Escreva um programa que cause, de propósito, um erro de compilação (ex.: esqueça o ponto e vírgula). Compile e leia a mensagem. Depois conserte e compile de novo até emitir nenhum erro/aviso.

Dica: Tente trocar return 0; por return 0 e veja onde o erro aparece.

Ver solução
#include <stdio.h>

int main(void)
{
    printf("O erro já se foi\n");
    return 0;
}

Repare que o tipo da mensagem de erro muda conforme o erro: "error" (bloqueia a compilação) vs "warning" (compila mas é suspeito).

Nível 2

Exercício 0.01.3

Declare uma variável inteira x = 7 e um y = 4, imprima a soma, subtração, multiplicação e divisão inteira dos dois. O que acontece com 7/4? Compile com -Wall -Wextra.

Dica: Divisão de inteiros em C trunca o resto. Experimente imprimir 7.0/4 também usando um literal float.

Ver solução
#include <stdio.h>

int main(void)
{
    int x = 7, y = 4;
    printf("soma: %d\n", x + y);
    printf("subtracao: %d\n", x - y);
    printf("multiplicacao: %d\n", x * y);
    printf("divisao inteira: %d\n", x / y);      /* 7/4 = 1 (resto 3) */
    printf("divisao real: %.2f\n", 7.0 / 4.0);   /* 1.75 */
    return 0;
}

O literal 7.0 é ponto flutuante, o que muda o tipo da operação. Veremos tipos a fundo na Trilha 1.

Nível 2

Exercício 0.01.4

Usando o gdb: compile eu.c com -g, abra com gdb ./eu.exe, coloque um breakpoint em main, rode, avance com next e saia com quit.

Dica: Depois de run, o programa pausa em main. Cada next executa uma linha.

Ver solução
> gcc -g -Wall -Wextra -std=c11 eu.c -o eu
> gdb ./eu.exe
(gdb) break main
Breakpoint 1 at ...
(gdb) run
(gdb) next
(gdb) next
(gdb) quit

Se o gdb pedir para sair com "Quit anyway? (y or n)", responda y.

🏗️ Miniprojeto: Cartão de visita em C

Crie um programa cartao.c que imprime um "cartão de visita" ASCII: seu nome, papel/objetivo de estudo e um dos seus hobbies. Use printf com \n e pelo menos um caractere de borda (ex.: +---o---). Compile com -Wall -Wextra -std=c11 e garanta zero avisos.

Critérios de aceite

  • Programa compila com gcc -Wall -Wextra -std=c11 cartao.c -o cartao sem erros nem avisos.
  • Saída contém seu nome, objetivo e um hobby, formatada com bordas ou separadores.
  • Função main retorna 0.
  • Você consegue explicar cada linha para outra pessoa.
